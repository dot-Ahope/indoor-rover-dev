## 1. 증상 · 왜 필요했나
- 09-07 오전(받침대, PWM 50 Hz 상태): 구속된 휠에서도 FG 펄스가 50 Hz 로 나와 15 mm/s 로 환산 → 펌웨어가 '돌고 있다' 고 봄 → 저 duty 구속은 펌웨어 단독으로 못 잡음. 그래서 "Jetson 측 rover-level 정체 감지(지령 vs EKF/스캔 변위, 2s) 추가를 N1 전제조건으로 격상"(CLAUDE.md '안전은 펌웨어' 원칙의 예외로 명시). [09-07 「결론 (측정 기반)」 L41 · 「설계 결정」 L48](../debug_log/2026-09-07/SUMMARY.md)
- 같은 날 PWM 을 20 kHz 로 고치자 구속 휠 펄스는 0 이 돼 펌웨어 스톨 감지는 정상화됐다(→ [스톨 래치 카드](stall-latch.md)). 그래도 이 노드가 남은 이유는 오후의 54e: MPPI 가 벽을 긁는 동안 휠은 계속 돌아 펌웨어도, 휠 오도 기반 EKF 도 '이동 중' 으로 봤다. [09-07 L331~334](../debug_log/2026-09-07/SUMMARY.md)
- 09-07 「다음 작업」 1 의 사양: "지령 \|v\|>0.015 or \|ω\|>0.1 이 2s 지속인데 **EKF 변위** <1cm · yaw<2° → goal cancel + cmd_vel 0 + 진단". 실제 구현은 EKF 가 아니라 **라이다 스캔**을 썼다(§6 — EKF 는 휠 오도를 쓰므로 헛돎을 못 본다는 같은 날의 논리와 맞추려면 이쪽이 맞다).

## 2. 동작 원리 (09-10 판 `d9d67b25` 기준, 코드 읽기)
**입력**: `/cmd_vel`(Twist — 컨트롤러 · smoother 출력뿐 아니라 behavior_server 의 BackUp · Spin 명령도 같은 토픽이라 함께 들어옴), `/scan`(LaserScan, sensor_data QoS), 선택 `/imu/data`(`use_gyro`, 09-08 부터 기본 끔), `/<backup|spin|drive_on_heading|wait|assisted_teleop>/_action/status`(09-09 ~). 시간은 모두 **벽시계** `time.time()`.

**파라미터(기본값)**: `window` W = 2.0 s · `v_thr` 0.015 m/s · `w_thr` 0.10 rad/s · `ratio` 0.25 · `confirm` 2 · `cooldown` 5.0 s · `rate` 5 Hz · `shadow_mode`(런치 `stuck_shadow`) · `use_gyro` false.

1. **스캔 → 1° 프로파일**(`profile`): 유효 거리(`range_min` < r < min(`range_max`, 12 m))의 각을 `angle + LIDAR_YAW`(당시 π — 라이다가 180° 돌려 달림; 09-18 에 π − 0.04677 로 동기화)로 로버 기준으로 바꿔 360 칸에, 같은 칸은 **최소 거리**. 빈 칸은 nan.
2. **5 Hz 마다**(`tick`): 버퍼를 W + 0.5 s 로 자르고 창 W 안의 **지령 적분** `dist_cmd = ∫|v|dt`, `ang_cmd = ∫|ω|dt`(사다리꼴이 아니라 '뒤 샘플 값 × 간격' 의 직사각 적분 — 코드 주석의 '사다리꼴 근사' 와 다름).
3. **판정 대상인가**: `dist_cmd ≥ v_thr × W = 0.03 m` 또는 `ang_cmd ≥ w_thr × W = 0.2 rad(11.5°)` 가 아니면 판정 안 함(누적 카운트 0 으로). 즉 **평균 1.5 cm/s 또는 5.7 °/s 미만으로 기는 명령은 보지 않는다**.
4. **회전 관측**: 창 시작(now − W) 이전의 마지막 스캔 A 와 최신 스캔 B 의 프로파일을 순환 상관 → B 를 몇 칸 돌리면 A 와 맞나. 09-07 판은 −179 ~ +179 전수 탐색(비용 = 겹치는 칸의 \|A − roll(B)\| 중앙값, 겹침 ≥ 30 % 필요) + 포물선 보간. 09-08 판은 FFT 순환 상관(`irfft(rfft(a)·conj(rfft(b)))`, nan → 0 · 평균 제거)으로 후보 d0 → d0 ± 2 만 원래 비용으로 세밀 탐색 + 포물선(±1 칸). 09-07 판은 자이로 적분 ∫\|ω_gyro\|dt 와 **큰 쪽**을 관측 회전으로.
5. **병진 관측**: B 를 정수 칸만큼 되돌린 뒤 정면(0°) · 후면(180°) ±20° 섹터에서 A − B 의 중앙값(두 값 모두 3 m 미만인 칸이 8 개 이상일 때만). 두 섹터 중 **큰 \|값\|**. 정면 · 후면 모두 무효면 병진 판정 근거 없음.
6. **비율**: 병진 지령이 문턱 이상이고 병진 관측이 유효하면 `trans_obs / dist_cmd`, 회전 지령이 문턱 이상이면 `rot_obs / ang_cmd(°)`. 비율이 하나도 없으면 보류. 있으면 **둘 중 큰 값**(어느 한 축이라도 움직였으면 '움직였다').
7. **확정 · 조치**: 비율 < 0.25 가 **연속 2 틱**(5 Hz 라 0.2 s 간격 — '연속 2 회 판정' 은 두 창이 아니라 거의 같은 창을 두 번 본 것)이고 직전 조치에서 5 s 지났으면 `on_stuck`: 경고 로그 `STUCK: 지령 X cm/Y° 인데 관측 x cm/y° (비율 r)`, `/rover/stuck` 에 DiagnosticArray(그림자 = WARN, 작동 = ERROR, 값 ratio · shadow). 작동 모드면 `/navigate_to_pose/_action/cancel_goal` 에 빈 요청(= **그 서버의 모든 목표 취소**) + `/cmd_vel` 0 × 10(주기 발행 아님).
8. **복구 중 보류**(09-09 추가, 09-10 정정): 복구 행동 상태 메시지에 EXECUTING(2)이 있으면 `recovery_active = True`, 모든 목표가 종료(4 · 5 · 6)면 `False` — 둘 다 `recovery_until = now + W`. 틱에서 `recovery_active or now < recovery_until` 이면 판정 안 함(누적 0).

**합성 자체시험**(`--selftest`, PC · Jetson 어디서나): 사인파 프로파일을 15° 돌린 것 → 회전 추정 15.0, 정면 ±20° 를 5 cm 당긴 것 → 병진 추정 0.05(09-07 L363 "15°→15.0, 5cm→5.0cm").

## 10. 용어
- **rover-level 정체 감시**: 휠 회전(펌웨어 · 휠 오도)과 무관한 센서로 차체가 실제로 움직였는지 확인하는 감시. 펌웨어 스톨 보호(휠 구속)의 보조.
- **그림자(shadow) 모드 · 작동(active) 모드**: 그림자 = 판정만 로그 · 진단으로 남기고 조치 안 함(새 안전 로직을 실주행에서 오탐 0 확인하는 단계), 작동 = 목표 취소 + 정지 명령.
- **정탐 · 오탐**: 정체가 맞을 때 잡음(정탐), 정상인데 정체로 판정(오탐 — 주행을 쓸데없이 끊음).
- **순환 상관(FFT)**: 360° 프로파일 둘을 한쪽을 돌려 가며 겹쳐 보는 계산을 FFT 곱으로 한 번에(O(N log N)). 최대가 되는 회전량이 두 스캔 사이 로버 회전.
- **액션 상태 토픽 `_action/status`**: ROS 2 액션 서버가 자기 목표들의 상태(1 수락 · 2 실행 중 · 4 성공 · 5 취소 · 6 중단) 목록을 내는 숨김 토픽. **상태가 바뀔 때만** 발행된다.
- **CancelGoal 빈 요청**: 목표 ID 와 시각이 0 이면 그 액션 서버의 모든 목표를 취소한다.

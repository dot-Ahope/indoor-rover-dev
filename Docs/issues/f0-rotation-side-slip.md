## 10. 용어
- **스키드스티어 제자리 회전**: 좌우 트랙을 반대로 돌려 그 자리에서 도는 것. 트랙은 땅 위를 옆으로 긁으며 돈다(슬립이 전제). 좌우 슬립이 같으면 중심을 축으로, 다르면 축이 한쪽 트랙 쪽으로 옮겨져 **중심이 원을 그리며 옆으로 밀린다**. 휠 오도는 '중심 축 회전' 을 가정해 옆 이동을 0 으로 보고한다.
- **불가관측(unobservable)**: 필터에 들어오는 어떤 센서도 그 양을 재지 않는 상태. 여기서 EKF 입력은 휠(vx · vy = 0 · vyaw)과 자이로(yaw rate)뿐이라 옆 속도를 재는 입력이 없다 → 얼마나 공분산을 바꿔도 EKF 는 옆 밀림을 추정할 수 없다(§20.5 '가변 vy 단독은 효과 없음' 의 이유).
- **map→odom 보정 · REP-105**: ROS 의 좌표 사슬 map → odom → base_link. EKF 는 odom→base_link(연속, 튀지 않음), SLAM 은 map→odom(지도와 맞추는 보정, 튈 수 있음). 그래서 SLAM 이 맞추는 것은 map 좌표이고, odom 좌표로 그리는 로컬 코스트맵 · nvblox · MPPI 는 그 보정을 직접 받지 않는다.
- **풋프린트 계단 판정**: 코스트맵은 5 cm 칸이다. Nav2 는 차체 꼭짓점을 칸으로 내림하고 변을 Bresenham 직선으로 따라가 지나는 칸의 최대 비용을 본다. 그래서 차체가 기하적으로 LETHAL 칸에서 4.4 cm 떨어져 있어도 변이 그 칸 '안' 으로 계산될 수 있다(반올림 계단). 해상도를 낮추면(0.025) 계단이 줄지만 계산이 늘어난다.
- **내접 비용(99) · LETHAL(100)**: OccupancyGrid 로 발행된 코스트맵 값. 100 = 장애물 칸, 99 = 차체 내접원이 닿는 거리(중심이 여기 오면 반드시 충돌).
- **헛돎형 vs 측면 슬립형(이 카드의 구분)**: 헛돎형 = 휠은 돌았는데 몸체가 덜 돎(휠 yaw ≫ 자이로 yaw, n62b) — 자이로가 있어 EKF 가 잡는다. 측면형 = 회전량은 맞는데 중심이 옆으로 밀림(휠 ≈ 자이로, f0a2) — EKF 가 못 잡는다.
- **rf2o · cuVSLAM**: rf2o = 연속 라이다 스캔 정합으로 차체 속도(vx · vy · ω)를 내는 라이다 오도메트리. cuVSLAM = NVIDIA 의 GPU 스테레오(+IMU) 비주얼 오도메트리. 둘 다 '옆 속도' 를 잴 수 있어 D 의 후보.
- **가변 공분산(variable σ)**: 센서 값의 믿음 정도(σ)를 상황에 따라 바꾸는 것. 여기선 '제자리 회전 중엔 휠의 옆 속도 0 주장을 덜 믿는다'.
- **스캔 직접 정합(ICP, 이 카드의 '정답')**: 회전 전 · 후 **정지** 상태의 라이다 스캔 두 장을 겹쳐 맞추는 강체 변환(회전 θ + 이동 t)을 반복 최근접점으로 구하는 것. SLAM · 휠 · 자이로를 쓰지 않으므로 그 셋을 판정하는 독립 기준이 된다. 벽 · 가구 같은 구조가 둘레에 있어야 하고, 움직이는 중의 스캔에는 못 쓴다(09-28 `job567`).
- **M1′**: §1 의 M1(SLAM vs 줄자)이 원본 SLAM 의 순수 회전 스캔 미처리로 성립하지 않아 바꾼 판정 — 스캔 직접 정합 vs 줄자, 기준 3 cm 그대로.
- **같은 방향 반복 vs 교대(바닥 기준 누적)**: 밀림 방향은 회전을 시작할 때 차체 기준으로 일정(시계 = 왼쪽)하다. 180° 마다 차체가 뒤집히므로 같은 방향으로 두 번 돌면 바닥 기준으로 반대쪽 → 상쇄, 시계 · 반시계를 번갈아 돌면 바닥 기준 같은 쪽 → 누적(§5.1). 회전마다 크기가 다르면 상쇄도 덜 된다(R3).
- **목표 yaw `a` · `p`**: 러너가 Nav2 목표의 방향을 정하는 방식. `a` = 직전 지점 → 목표 직선 방향, `p` = 보내기 직전 계획기에 경로를 물어 **경로 끝 0.3 m 의 진행 방향**. 둘 다 '도착한 그 방향 그대로 성공' 이 되게 해 목표에서 제자리 회전을 요구하지 않으려는 것.
- **stateful 목표 판정기 · xy 진입**: Nav2 `SimpleGoalChecker` 의 stateful 모드는 위치(xy 허용)가 한 번 맞으면 그것을 잠그고 방향(yaw 허용)만 본다. 'xy 진입' = 목표까지 거리가 xy 허용(0.15 m) 안에 처음 든 순간. 잠근 뒤 제자리 회전에서 생기는 밀림은 그대로 최종 오차가 된다(§19).
- **GoalCritic · GoalAngleCritic · PreferForwardCritic(MPPI)**: 목표 근처에서 켜지는 크리틱. GoalCritic = 목표 위치까지 거리(가중 10), GoalAngleCritic = 목표 방향 차(가중 3, 0.4 m 안), PreferForward = 후진 벌점(0.4 m 안에선 꺼짐 — §20 서술). 경로 크리틱(PathAlign 등)은 목표 0.2 m 안에서 꺼진다(§15 서술 — 09-28 당시 설정, 지금 값은 `nav2_params.yaml` 확인 필요).
- **odom 층 어긋남(f0a3)**: 로컬 코스트맵 · nvblox 는 odom 프레임에 장애물을 기억한다. odom 이 회전 슬립을 못 보면 로버는 실제로 밀렸는데 odom 좌표는 그대로라, 이미 기억한 상자가 map(실제)에서 보면 밀림만큼 옮겨진 자리에 남는다. SLAM 이 map→odom 을 고쳐도 odom 층 안의 기억은 고쳐지지 않는다.

**한 줄**: 08-26 에 1:90 모터(CHR-GM37-BLDC3650)로 바꿀 때 이관 계획서의 T1 '속도 PWM 20 kHz(권장 15~25 kHz)' 가 펌웨어에 들어가지 않아, 모터 속도선(청색)에 **구모터용 50 Hz** PWM 이 그대로 걸려 있었다. 09-07 받침대 스톨 시험에서 '트랙을 나무토막으로 고정해도 바퀴 속도가 14~28 mm/s 로 보고되는' 현상을 휠별 텔레메트리로 쫓다가, 구속된 바퀴의 FG 펄스 주기가 **정확히 20.0 ms / 10.0 ms**(50 Hz 와 그 2 배)라는 서명을 얻었고, 그 뒤 계획서와 코드를 대조해 원인을 찾았다. 20 kHz 로 바꾸자 구속 바퀴 펄스가 0 이 되어 스톨 감지 · 자동 복구 · 하드 래치가 처음으로 전 경로 동작했고, duty–속도 관계가 선형(duty ≈ 0.36 + 4.5·v, 구 단위)이 되었으며 바닥 데드밴드도 사라졌다. 같은 날 오전에는 이 현상을 'FG 방식의 근본 한계' 로 결론 내리고 PWM 변경을 '사양 미확인 · 위험' 으로 기각했었다(§6 실수 ①②). 반대로 50 Hz 탓으로 짐작했던 직진 스케일 28.7 % 과대는 20 kHz 뒤에도 그대로라 휠 둘레 상수 오류로 갈렸다(§6 실수 ③).

### 4.3 한계
- 기전(왜 50 Hz 에서 서 있는 바퀴가 펄스를 내나)은 끝내 확인 안 함 — 두 해석(FG 게이팅 / 토크 맥동에 의한 홀 경계 떨림) 모두 **추정**.
- 20 kHz 가 '권장 범위 안' 이라는 것 외에, 드라이버가 어떤 방식으로 PWM 을 속도 지령으로 읽는지(평균 전압 · 펄스 폭 측정 등)는 판매자 사양에 없음 — 미확인.
- 하드 잼 시 드라이버 자체 보호가 있는지는 이번에도 확인 못 함(「결론」 3).

## 9. 도구 해설
`job40a_stalltest.py`(Run 1~J 와 정착점 전부를 만든 도구) · `run_sig.sh` · 휠별 텔레메트리 펌웨어의 상세는 [스톨 카드 §8.6~§8.10](stall-latch.md). 이 카드에서 덧붙일 것만 적는다.

### 9.1 `job42*` · `job41*` 는 별도 스크립트가 아니다
- `jobs/` 에 `job41*.py` · `job42*.py` 가 없다. 출력 이름 `job41a_free002` · `job42a_20k_blockL` 등은 **`job40a_stalltest.py` 를 인자만 바꿔 부른 회차 이름**이다(첫 줄 `cmd_vel vx=… for …s (20Hz)` 가 그 도구의 출력 형식). 이름 규칙: `free`(자유) / `blockL`(좌 구속) + 지령(002 = 0.02 m/s), `20k` = 20 kHz 펌웨어, `tuned` = 재튜닝 FF, `min030` · `min040` = 그때 의도한 MIN 값.
- 주의: 이름이 **의도**를 적은 것이지 실제 상태가 아닌 경우가 있다 — `job41h_blockL003_min030` 은 플래시 실패로 MIN 0.020 상태였고(SUMMARY 「Run H」 ⚠), `job41e_blockL005` 는 SUMMARY 표에서 '(구속 안 함) … 자유 회전 데이터로 취급'.
- 0.2 s 간격 회차(`job41g` 부터 · `job41h` · `job41i` · `job42*`)는 4 번째 인자 `LOG_DT 0.2` 를 쓴 것 — 이 인자는 커밋 `8fd76182` 에서 도구에 추가됐다. `run_sig.sh` 는 인자 2 개(DUR · VX)만 넘기므로 이 회차들을 어떤 감싸개로 불렀는지는 **원천 소실**.

### 9.2 `integrated_bldc_driver.c` 의 PWM 블록 — '원인이 된 코드'
- 위치: [`../../firmware/rover_jupiter_fw/App/drivers/integrated_bldc_driver.c`](../../firmware/rover_jupiter_fw/App/drivers/integrated_bldc_driver.c) 상단 매크로(`PWM_TICK_HZ` · `PWM_FREQ_HZ` · `PWM_ARR` · `TIM1_PSC_1MHZ` · `TIM3_PSC_1MHZ`)와 `bldc_init()`.
- 하는 일: 초기화 때 TIM1(좌, PA11 CH4) · TIM3(우, PC6 CH1)의 prescaler · auto-reload 를 위 매크로로 덮어쓰고 카운터 0 → `bldc_set_duty()` 가 `|duty| × (ARR+1)` 을 compare 레지스터에 씀. 방향은 백색선 GPIO 레벨(`DIR_*_FWD_LEVEL`), duty ≠ 0 일 때 방향 부호를 `s_dir_sign` 에 기록(FG 속도 부호 주입용 `bldc_last_dir_sign()`).
- 왜 여기서 놓치기 쉬웠나: CubeMX 생성 `Core/Src/tim.c` 에는 PSC 0 · Period 65535 만 있어 주파수가 보이지 않는다. 주파수를 확인하려면 이 파일을 읽어야 한다.
- 계보: 06-26 50 Hz(구모터 '사용자 확정 ①') → 09-07 20 kHz(롤백 값 주석 보존). 지금도 이 판.

### 9.3 서명 읽는 법(이 시기 텔레메트리로)
- 서 있는 바퀴인데 `pps > 0` 이고 `T` 가 `20000±` 또는 `10000±` µs 에 붙어 있으면 **50 Hz 기저 펄스**. 진짜 회전은 `T` 가 속도에 따라 연속적으로 변한다(예 20 kHz 자유 0.04 → `T` 5.7~7.5 ms).
- `cv=0` 은 '아주 규칙적' 이 아닐 수 있다 — 200 ms 창에 펄스가 8 개 미만이면 펌웨어가 cv 를 0 으로 **강제**한다(스톨 카드 §8.10). 예 `job41c` 의 `pps=35 T=4834 cv=0`.

## 10. 용어
- **PWM 주파수**: PWM 이 1 초에 켜짐/꺼짐을 반복하는 횟수. 50 Hz = 20 ms 주기, 20 kHz = 50 µs 주기. 이 모터의 청색선은 PWM 의 duty 를 '속도 크기' 로 읽는다(사양 표 · 드라이버 주석). 사양 권장은 15~25 kHz.
- **tick · PSC · ARR**: 타이머 카운터가 세는 클럭(tick) = 타이머 클럭 ÷ (PSC+1). PWM 주기 = (ARR+1) tick. duty 분해능 = ARR+1 단계 — 20 kHz 에서 1 MHz tick 이면 50 단계뿐이라 84 MHz tick 으로 올렸다.
- **FG(Frequency Generator) 펄스 · 홀 센서**: 모터 내부 3 상 홀 센서의 전이에서 나오는 펄스(이 모터 휠 1 회전당 542 개 실측). 방향 정보가 없어 펌웨어가 마지막 지령 방향을 부호로 붙인다.
- **기저 펄스(이 카드의 말)**: 바퀴가 서 있는데도 PWM 주기에 맞춰 나오던 FG 펄스(50 Hz 모드 20.0 ms · 100 Hz 모드 10.0 ms). 가짜 속도 ≈ 15 · 30 mm/s(구 단위).
- **하드 잼**: 바퀴가 완전히 고정돼 펄스가 0 이 된 구속(Run F · G 의 duty 94~98 % 구간). 50 Hz 에서는 이 경우만 스톨로 잡혔다.
- **토크 맥동**: 구동 전류가 주기적으로 켜졌다 꺼지며 회전력이 출렁이는 것. 50 Hz 는 기계가 따라 떨 수 있을 만큼 느리다(이 카드의 기전 해석 중 하나 — 추정).
- **정착점**: 폐루프 제어에서 목표 속도에 도달해 머무를 때의 duty. 20 kHz 정착점을 이어 FF(`DEADZONE` · `KV`)를 다시 맞췄다.
- **FF · 스톨 · 래치**: [데드밴드 카드 §9](start-deadband.md) · [스톨 카드 §9](stall-latch.md).

**한 줄**: Nav2 컨트롤러가 내는 작은 명령(바퀴 속도로 수 mm/s ~ 1 cm/s)에 로버가 아예 반응하지 않아, 컨트롤러는 '측정 속도 0' 을 보고 같은 작은 명령을 끝없이 반복했다(RPP 회전 시작 데드락 · MPPI 목표 앞 정체 · 장애물 옆 배회). 09-02 에 RPP 쪽은 가속 제한을 풀어 우회하고, 근본 보상으로 펌웨어에 '최소 기동 바퀴 속도 승격'(0.003 ≤ |v| < MIN → MIN)을 넣었다. 09-03 에 빌드 환경을 되살려 플래시하고 MIN 을 0.012 · 0.016 · 0.020 으로 바꿔 가며 쟀더니 기동 문턱은 0.012~0.016 m/s(당시 펌웨어 단위)였고, 여유를 둔 **0.020** 으로 확정했다. 다만 ① 이 측정은 모터 PWM 이 잘못 50 Hz 로 걸려 있던 조건이었고(09-07 발견), ② 09-02 데드락의 직접 원인 일부는 기계 마찰이 아니라 **펌웨어 속도 제어기의 정지 문턱(0.01 m/s)이 그 명령을 '정지' 로 버린 것**이었다(이 카드 작성 중 코드 읽기로 확인, 09-17 실측과 일치). 그리고 승격된 0.020 이 스톨 감지 문턱(0.015) 바로 위라 [스톨 래치](stall-latch.md)를 불렀다. **09-07**: 받침대 스톨 시험에서 승격값은 '스톨 감지 체인의 손잡이' 로도 다뤄졌다 — 50 Hz 의 가짜 바퀴 속도(15 mm/s)를 넘기려 0.030 을 제안했다가 100 Hz 모드(30 mm/s)와 겹쳐 철회, 0.040 으로 시험. 그 뒤 원인(PWM 50 Hz)을 고치자 받침대 10~100 mm/s 가 1 s 안에 정착했고(duty ≈ 0.36 + 4.5·v), 바닥 직진 스윕 `job44a` 에서 구 10 mm/s 도 좌우 대칭으로 추종 → 09-03 문턱은 50 Hz 산물로 폐기, MIN 은 0.010(임시) → 휠 둘레 정정에 따른 환산 **0.008**. 이 환산 때 속도 제어기 정지 문턱(0.010)은 그대로 둬 승격된 지령이 다시 '정지' 로 버려지는 결함이 생겼고(09-17 발견), 헤더 주석은 '데드밴드 사실상 없음' 으로 미검증 구간까지 일반화했다(§5 실수 ④). **09-17**: MPPI 가 목표 앞에서 9 mm/s 로 기어가려다 멈추는 일이 mp6 · mp8 에서 나왔고(나는 mp6 때 다시 '모터 데드밴드' 라고 적었다 — 실수 ⑤), mp8 bag 의 보드 상태에서 **휠 목표 자체가 0** 인 것을 보고 'MIN 0.008 < STOP 0.010' 결함을 확인했다. 사용자 결정으로 문턱을 헤더 한 곳에 모으고 STOP 을 5 mm/s 로 낮췄으며 순서(EPS < STOP ≤ MIN)를 `#error` 로 검사하게 했다. 정지 출발 실측(`job397`)에서 직진 8 mm/s · 제자리 회전 ±8 mm/s 가 양 휠 기동해 MIN 0.008 이 처음으로 실측값이 됐다. 목표 앞 정지의 주 원인은 시뮬상 Nav2 목표 근처 크리틱 설정이었고(같은 날 함께 바꿈), 펌웨어 결함은 그것을 '영원한 정지' 로 만든 보조 원인으로 판정했다(근거는 시뮬).

### 8.8 펌웨어 코드 해설 (09-03 커밋 `42ea9579` 판)
- **명령 경로**(`App/microros/microros_task.c` `cmdvel_callback()`): `/cmd_vel` 의 `linear.x` 를 ±`V_MAX_MPS`(= `MAX_LINEAR_SPEED_MPS` 0.100) 로 자름 → 차동 역기구학 `v_l = v − ω·0.1225`, `v_r = v + ω·0.1225`(`HALF_WHEEL_BASE = WHEEL_BASE_M 0.245 / 2`) → 한쪽이 0.100 을 넘으면 두 바퀴를 같은 비율로 줄여 회전 방향 보존 → **`apply_min_wheel_speed()`** 를 좌 · 우 각각 → `speed_controller_set_target()` → `safety_monitor_cmdvel_received()`(watchdog 시각 갱신).
- **`apply_min_wheel_speed(v)`**: `|v| < WHEEL_SPEED_EPS_MPS(0.003)` → 0(정지 의도 유지), `|v| < MIN_WHEEL_SPEED_MPS(0.020)` → `copysignf(0.020, v)`(부호 보존 승격), 그 밖은 그대로. 승격은 **포화 축소 뒤**에 하므로 축소로 작아진 바퀴도 승격된다. 부작용: 한쪽만 승격되면 곡률이 지령과 달라짐(주석: '상위 피드백 루프가 흡수').
- **`speed_controller_set_target()`**(`App/app/speed_controller.c`): `|target| < TARGET_THRESH(0.01)` 이면 목표를 바꾸지 않고 `stop_ramp` 모드(4.0 m/s² 로 0 까지 감속 후 duty 0). 승격 전에는 바로 여기서 6 mm/s 가 '정지' 가 됐다(§5 실수 ①).
- **`speed_controller_update()`**(100 Hz, `freertos.c` 의 제어 태스크에서 `encoder_update_velocity → speed_controller_update → safety_monitor_update → odometry_update` 순): 목표 < 0.01 이면 적분 · duty 0. 아니면 `integral += Ki(6.0) · err · 0.01`(±`I_MAX 0.85` 클램프), `duty = sign(tgt) · DEADZONE(0.13) + KV(12.0) · tgt + Kp(0.7) · err + integral`, ±`OUT_MAX 0.98` 로 자르고, 통합 BLDC 는 목표와 반대 부호 duty(제동)를 0 으로(방향선 thrash 방지). `last_duty` 에 저장 — 이 값이 [스톨 카드](stall-latch.md)의 duty 기준 판정에 쓰인다.
- **상수의 출처**: `DEADZONE 0.13`(최소 기동 duty 실측 ~15 % 의 살짝 아래), `KV 12`(08-26 duty-속도 곡선 절충), `I_MAX 0.85`(50 mm/s 에 70 % 포화 관측 뒤 상향) — 전부 08-26 · PWM 50 Hz 조건. `MAX_LINEAR_SPEED_MPS 0.100`(duty 98 % 에서 0.115 m/s 실측에 여유).

### 8.10 `job42b` · `job42c` 정착점 회차 — 도구는 `job40a_stalltest.py`
- 부른 형태(출력 첫 줄로 확인): `vx = 0.04 / 0.06 / 0.08 / 0.10`(`job42b`, 구 FF) · `0.01 / 0.02 / 0.03 / 0.05 / 0.10`(`job42c`, `DEADZONE 0.34` · `KV 4.5`), 각 7 s, 0.2 s 간격, 받침대 무부하. 도구 상세는 [스톨 카드 §8.6](stall-latch.md).

## 9. 용어
- **데드밴드(기동 데드밴드)**: 명령이 0 이 아닌데도 출력(바퀴 회전)이 0 인 입력 구간. 여기선 두 층 — ① 펌웨어가 의도적으로 '정지' 로 보는 구간(`TARGET_THRESH 0.01`, `EPS 0.003`) ② 모터 · 트랙이 실제로 못 움직이는 구간(정지마찰 · 저속 제어 한계, 09-03 실측 0.012~0.016).
- **정지마찰(static friction)**: 멈춰 있는 물체를 움직이기 시작하는 데 드는 힘이 이미 움직이는 물체를 계속 움직이는 힘(운동마찰)보다 큰 성질. 그래서 '움직이기 시작할 때만' 큰 힘이 필요하고, 계획 §6.1 의 '움직인 뒤 저속 능력을 못 씀' 한계가 여기서 나온다.
- **승격(promotion)**: 문턱 아래의 0 이 아닌 명령을 문턱 값으로 올려 실행(부호 보존). 대가는 분해능 — 승격 구간 안의 명령은 크기와 무관하게 같은 속도.
- **기동 보조(kick-start, 계획의 '적응형')**: 멈춰 있을 때만 잠깐 문턱 이상으로 밀고 움직이기 시작하면 원래 작은 목표로 돌아가는 방식. 이 시기엔 제안만 됨.
- **duty**: PWM 한 주기 중 켜져 있는 비율(0~1). 이 모터는 '내장 속도 제어' 로 추정돼(08-26) duty 가 곧 전압이 아니라 속도 지령처럼 동작한다. 이 시기 PWM 주파수는 잘못 50 Hz 였다(09-07 에 20 kHz 로 정정).
- **feedforward(DEADZONE · KV)**: 오차를 보기 전에 '이 속도면 대략 이 duty' 를 미리 더하는 항. PID 는 그 위에서 잔차만 보정.
- **RPP 각가속 클램프**: [Nav2 카드 §9](nav2-first-setup.md) RPP 항목.
- **스톨 · latch · re-arm**: [스톨 카드 §9](stall-latch.md).
- **정착점(settling point)**: 폐루프로 목표 속도에 머무를 때의 duty. 이것을 여러 속도에서 이으면 duty–속도 곡선이 되고, 그 절편 · 기울기가 FF(`DEADZONE` · `KV`)가 된다. 20 kHz 에선 duty ≈ 0.36 + 4.5·v(구 단위)의 직선.
- **단위 환산(구 단위 → 실 단위)**: 09-07 휠 둘레를 0.16130 → 0.12533 으로 고치자 펌웨어의 'm/s' 가 실제 속도가 됐다. 구 단위 x m/s = 실 0.777·x m/s. 속도가 걸린 상수(MIN · KV · MAX · 정지 문턱 · 스톨 문턱)를 **모두** 같이 바꿔야 층 사이 관계가 유지된다(실수 ④).
- **층 사이 불변식 EPS < STOP ≤ MIN**: 정지 의도(EPS) 아래는 0, 승격 하한(MIN)은 속도 제어기의 정지 문턱(STOP) 이상이어야 승격된 지령이 버려지지 않는다. 09-17 에 `#error` 로 검사하게 됨.
- **기저 펄스 · PWM 주파수**: [PWM 카드 §10](motor-pwm-50hz.md).
- **정지 문턱(STOP, `SPEED_CTRL_STOP_THRESH`)**: 속도 제어기가 '이 아래 목표는 정지 명령' 으로 보고 감속 ramp 뒤 duty · 적분을 0 으로 만드는 값. 09-17 까지 10 mm/s(각 파일 지역 상수), 지금 5 mm/s(헤더).
- **정수 µm/s 매크로 · `#if/#error`**: C 전처리기 `#if` 는 정수 비교만 할 수 있어(부동소수 불가) 문턱을 `…_UMPS`(µm/s 정수)로 정의하고, float 값은 `× 1.0e-6f` 매크로로 만든다. `#if !(A < B)` → `#error "…"` 는 조건이 깨지면 **빌드 자체가 실패**하게 하는 컴파일 시 검사.
- **float 상수 바이트 패턴**: 32 bit float 는 메모리에 4 바이트로 저장된다(0.005f = 0x3BA3D70A, 리틀엔디언 바이트열 `0a d7 a3 3b`). 객체 파일 덤프에서 이 바이트열을 찾으면 그 상수가 코드에 들어갔는지 볼 수 있다(`fw_verify.sh`). 0.01 과 1/100 처럼 같은 값은 구별 못 한다.
- **`/rover/status` 휠 문자열**: 보드가 5 Hz 로 보내는 DiagnosticArray 값. `L=tgt=… v=… d=… pps=… T=… cv=… w=… sc=…` — 목표 · 측정 속도(mm/s), duty(%), FG 펄스/s, 펄스 주기(µs), 변동 계수, 창, 스톨 카운터. 09-07 부터(휠별 텔레메트리, [스톨 카드](stall-latch.md)).

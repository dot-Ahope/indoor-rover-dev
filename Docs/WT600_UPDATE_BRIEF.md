## 2. 핵심 문제 — WHEEL_BASE_M 불일치

- 펌웨어 `rover_platform.h`의 `WHEEL_BASE_M = 0.190`은 **구형 소형 차체 값**이었음.
- 실측 게이지 0.245 → 구펌웨어는 휠오돔 yaw를 **약 1.29배(0.245/0.190) 과대** 계산.
- 2026-08-26 측정된 슬립 계수(0.42 @0.20rad/s, 0.28 @0.57rad/s)에는 이 기하 오차가 혼입됨.
  기하 보정 시 실제 슬립 계수는 ~0.53 수준으로 추정 — **반드시 재실측**.
- **W1 완료 · W2-1 완료**: `WHEEL_BASE_M = 0.245f` 수정됨 (2026-08-27). 빌드·플래시 대기.

## 3. 작업 순서

### W1 — 게이지 실측 ✅ 완료 (2026-08-27)
실측 0.245 m (바깥끝285−40 / 안쪽끝205+40 / 중심간 ~248 — 3법 수렴).

### W2 — 펌웨어 수정·플래시 (PC 측)
1. ~~`rover_platform.h`: `WHEEL_BASE_M` 0.190f → 0.29f~~ **수정 완료 (2026-08-27, Cowork 세션).**
   microros_task.c·odometry.c의 파생값 주석도 갱신됨. 실측 게이지가 0.29와 다르면 값만 재수정.
2. 빌드·플래시: **사용자가 직접 진행** (`BUILD_AND_FLASH_GUIDE.md` 절차) — 완료 통보 전까지 W4 진행 금지
3. 검증: 보드 재부팅 후 micro-ROS 토픽 정상 (`/wheel_odom` 50Hz)

### W3 — URDF 동기화 (Jetson 측)
1. 본 저장소 `Docs/rover.urdf` → Jetson `~/ros2_ws/src/rover_description/`에 반영, colcon 재빌드
2. 검증: RViz에서 TF 트리·센서 위치 확인. 스캔 vs 포인트클라우드 정합으로
   camera_link **y부호(±0.0475)** 판정 → URDF·본 문서에 결과 기입

### W4 — 슬립 재캘리브레이션 (Jetson 측, 바퀴 접지 상태 — 사용자 입회)
1. sensor_conditioner의 기존 슬립 계수(0.42/0.28) 무효화
2. 제자리 회전 재실측 (|vyaw| ≈0.20, ≈0.4 rad/s 2점 이상, 좌/우 회전 각각):
   실제 회전각(외부 기준) vs `/wheel_odom` yaw 비교 → 새 계수 산출·적용
3. 검증: 제자리 360° 회전 시 `/odometry/filtered` yaw 오차 <5%

### W5 — Nav2/SLAM 파라미터 정합 (해당 단계 진행 시)
- footprint: 0.50×0.33 (로봇 반경 ~0.30) — 구값 0.17 사용 금지
- 속도 한계: linear ≤0.08, angular ≤0.4 rad/s (슬립 캘리브레이션 신뢰 구간)

## 4. 주의

- `WHEEL_RADIUS_M`(0.02567)·`FG_PULSES_PER_REV`(542)는 **변경 금지** — 직선 캘리브레이션 유효.
- 펌웨어의 다른 파일은 건드리지 않는다. 안전 규칙은 `JETSON_SETUP_BRIEF.md` §3.
- 각 W단계 완료 시 검증 결과 보고 후 사용자 승인을 받고 다음 단계 진행.
- `Docs/전자회로기초/`, `Docs_Beginner/`는 학습 자료 — 읽지 않는다.

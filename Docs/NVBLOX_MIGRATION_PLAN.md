# nvblox 이전 계획 (2026-09-09 수립)

## 0. 결정

**현재 스택(Nav2 + STVL)을 먼저 완성하고, 그 다음 Isaac ROS nvblox 로 이전한다.**

Jetson Orin Nano 를 쓰고 있으므로 GPU 를 놀리는 것은 낭비이고, TSDF/ESDF 를 GPU 에서 만드는
nvblox 가 이 하드웨어에 더 맞는다는 판단. 다만 **이전 자체가 목적이 아니라 성능 향상이 목적**이므로,
비교 기준선을 수치로 고정한 뒤 A/B 로 판정한다.

> ⚠ 오늘(09-09) 확정된 사실 하나를 전제로 깔아 둔다. 상자가 코스트맵에서 사라지던 근본 원인은
> **카메라가 근접 시 깊이점을 못 만드는 것**이다(job167 지표 ⑤: 로컬이 상자를 잃은 81샘플 중
> 깊이점이 있었던 것 **0%**). nvblox 도 같은 깊이 입력을 받으므로 **같은 사각지대를 갖는다.**
> TSDF 누적이 STVL 감쇠보다 자연스럽게 버텨 주긴 하겠지만, 입력이 없는 구간은 그대로다.
> 따라서 **S2(사각지대 축소)는 이전 전에 반드시 끝낸다** — nvblox 로 옮긴다고 해결되지 않는다.

## Phase S — 현재 스택 개선 (이전 전 완료 조건)

### S1. STVL 감쇠 시간 확정 — 진행 중

`voxel_decay` 15.0 → 30.0 적용, 검증 대기.

- 근거: job167 에서 깊이점 소실(t=4, 카메라~상자 0.45m)부터 로버가 상자를 완전히 지날 때
  (t≈26)까지 약 22초 필요한데 15초에 만료(t=19) → 계획 여유 −1.4cm, 최근접 0.4cm.
- **종료 조건**: 로버가 상자를 완전히 지날 때까지 `lc_box` 유지, 실제 최근접 ≥ 5cm.

### S2. 카메라 사각지대 축소 ★ 이전 전 필수

`camera.launch.py` 의 `decimation_filter.filter_magnitude 4` 재검토 (→ 2 또는 off).

- 근거: job167 에서 깊이점이 **카메라~상자 0.51m → 0.45m 구간에서 142 → 0 으로 급락**했다.
  job71 실측 최소 측정거리 0.22~0.25m 보다 **훨씬 멀다**. 640×480 에 디시메이션 4 를 걸면
  유효 해상도가 160×120 이 되고, 디시메이션은 최소 측정거리를 키운다.
  **즉 사각지대를 우리가 스스로 넓혀 놓았다.**
- 대안: RealSense advanced mode(`json_file_path`) 의 disparity shift 로 최소거리 축소.
  `obstacle_range` 가 1.2m 뿐이라 최대거리를 내줄 여유가 있다.
- **측정**: 깊이점이 끊기는 카메라~물체 거리 / 포인트 수 / CPU 증가분.
- **종료 조건**: 끊김 거리 ≤ 0.35m, 그리고 CPU 증가가 `ekf_node` 의
  "Failed to meet update rate" 재발을 유발하지 않을 것.

### S3. 동적 장애물 망각 검증

상자 제거 시험. `decay_acceleration`(현 3.0) 튜닝.

- **종료 조건**: 상자 제거 후 로버가 그 구역을 절두체 안에서 다시 볼 때 소거되고,
  전역 코스트맵에 유령이 남지 않을 것.

### S4. 회피 주행 반복 검증

같은 코스 3회 연속.

- **종료 조건**: 접촉 0/3, 완주 3/3, 계획 좌우 전환 0, 직진 중 ω 부호반전 ≤ 1.0회/m,
  실제 최근접 ≥ 5cm.

### S6. CPU 여유 확보 ★ 2026-09-09 추가 — 우선순위 높음

`ekf_node` 의 주기 위반이 주행 정지의 뿌리로 확인됐다(§8.16).
CPU 부족 → EKF 지연 → `odom→base` TF 지연 → slam 이 스캔을 전부 폐기 → `map→odom` 미발행
→ `map→base_link` 조회가 tf2 버퍼(10초) 만료와 함께 실패 → 주행 중단.

- 최대 소비원: `sensor_conditioner` 35~37% (200Hz IMU 를 파이썬으로 중계).
  `gyro_fps` 인하는 **불가** — D455 자이로가 100Hz 프로파일을 지원하지 않는다(실측).
  → 컨디셔너에서 다운샘플하거나 C++ 로 옮긴다.
- `foxglove_bridge` 는 `viz:=lean` 으로 크게 줄었으나 클라이언트 접속 시 다시 오른다.
  측정 주행 중에는 끄는 것을 검토.
- **종료 조건**: 주행 30초 동안 `Failed to meet update rate` 0회,
  `Message Filter dropping` 0회, load < 6.

## Phase N — nvblox 이전

### N1. 환경 조사 (코드 변경 없음)

- JetPack 버전 확인 → 호환되는 Isaac ROS 릴리스 확정 (Isaac ROS 는 JetPack/CUDA 조합에 민감).
- `isaac_ros_common` 개발 컨테이너를 쓸지, 네이티브 설치가 가능한지 판정.
  현재 우리는 **네이티브 Humble + micro-ROS 에이전트만 컨테이너**다. 이 구조를 지킬 수 있는지가 핵심.
- **판정 게이트**: 현재 스택(펌웨어·EKF·SLAM·Nav2)을 건드리지 않고 nvblox 만 추가할 수 있는가.
  아니라면 이전 범위와 위험을 다시 산정한다.

### N2. nvblox 단독 기동

Nav2 에 연결하지 않고 TSDF/ESDF 생성만 확인.

- 입력: `/camera/camera/depth/image_rect_raw` + `camera_info` (nvblox 는 포인트클라우드보다
  깊이 이미지를 선호한다 — 이 경우 우리 포인트클라우드 파이프라인 일부가 불필요해진다).
- **측정**: GPU 사용률·전력·온도, ESDF 갱신 주기, 메모리.
- **판정 게이트**: 15W 모드에서 열·전력 여유가 있고, 배터리 주행 시간이 실용적일 것.

### N3. Nav2 코스트맵 연결

`nvblox_nav2` 코스트맵 레이어로 STVL 을 대체. **라이다 `obstacle_layer` 는 유지**한다
(레이어 분리 원칙: 센서는 자기가 감지할 수 있는 것만 지운다 — 09-09 §8.6).

- 설정은 **두 레이어를 모두 남기고 `plugins` 목록으로 전환**한다.
  재빌드 없이 A/B 가 가능해야 한다.

### N4. A/B 비교

S5 기준선과 **같은 코스·같은 스크립트**로 측정.

### N5. 채택 판정

- 채택: CPU 여유가 늘고 회피 지표가 동등 이상.
- 기각: STVL 로 복귀(`plugins` 한 줄). 브랜치는 기록으로 남긴다.

## Git 전략

### 브랜치

```
main
 └─ feature/wt600-migration   ← 현재. Phase S 를 여기서 마무리
      │
      └─(S5 완료 후 병합)──▶ main   + 태그 stvl-baseline
                               │
                               └─ feature/nvblox-migration   ← Phase N
                                    │
                                    └─(N4 통과 시)──▶ main
```

- **S5 전에는 main 에 병합하지 않는다.** 지금 스택은 오늘 하루에 링크·코스트맵·컨트롤러를 모두
  건드려 아직 검증 중이다. 검증이 끝난 상태만 main 에 올린다.
- **태그 `stvl-baseline`** 이 nvblox 실패 시 돌아올 지점이다. 태그 없이 브랜치만으로는
  "그때 그 설정" 을 재현하기 어렵다.
- **nvblox 는 반드시 별도 브랜치.** Isaac ROS 는 빌드 환경·의존성이 크게 바뀔 수 있어,
  실패 시 main 이 오염되면 안 된다.
- `feature/wt600-migration` 은 병합 후 삭제한다(오늘 시점 미푸시 커밋이 쌓여 있으므로
  병합 전에 반드시 push).

### 커밋 규칙 (오늘 방식 유지)

- **원인 1건 = 커밋 1개.** 메시지에 근거 수치를 넣는다(무엇을 재서 그렇게 판단했는지).
- **기각한 가설도 커밋에 남긴다.** 오늘 소거 계열 가설 3건을 기각한 기록이
  이후 판단의 근거가 되었다.
- **정정은 새 커밋으로.** 이전 커밋의 결론이 틀렸으면 지우지 말고 정정 커밋에 무엇이
  왜 틀렸는지 쓴다(오늘 `f1a76d8`, `35e0c12`, `dd519f6` 가 그 예).
- **비밀번호 스캔은 diff 가 아니라 '결과 내용' 을 본다.**

  ```bash
  git grep --cached -l "<금지 문자열>" | wc -l    # 0 이어야 커밋
  ```

  `git diff --cached | grep -c` 는 틀린 방법이다 — **삭제된 줄(`-`)까지 세므로**,
  비밀번호를 제거하는 커밋에서 오탐이 난다(2026-09-09 실제로 이 오탐 때문에 게이트가
  막혀 amend 가 안 됐다). 반대로 이 잘못된 검사를 게이트로 걸지 않고 출력만 하면
  유출을 그대로 커밋하게 된다 — 같은 날 그 사고도 냈다. **검사는 반드시 게이트로 건다.**

### Phase N 의 추가 규칙

- **환경 구성(N1)은 코드와 분리해 커밋**한다. Isaac ROS 설치·버전 고정은 되돌릴 일이 많다.
- nvblox 설정은 STVL 설정을 **지우지 말고 나란히 둔다**. `plugins` 목록만 바꿔 A/B.
- N2 이후 각 단계마다 `tegrastats` 로그를 `Docs/debug_log/` 에 남긴다.
  GPU·전력은 사후 재현이 어렵다.

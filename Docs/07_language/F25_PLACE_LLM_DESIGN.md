# F2.5 장소 이름 이동 + 온디바이스 LLM — 설계 (v0.2, 2026-10-28)

> 근거: 사용자 최종 목표(2026-09-30 §9) — "특정 구역에 이름을 붙이고, 온디바이스 LLM 에 '그 지역으로 이동해' 라고 하면 이동, '돌아와' 하면 출발 위치로 복귀".
> 결정된 것: 입력 = **텍스트**, 위치 = F2 다음 단계(`Docs/04_navigation/NAV2_EXPLORATION_PLAN.md §7.4` 4.5 행).
> 이 문서는 **아직 결정하지 않은 것**을 §8 에 모아 둔다. 수치 중 측정값은 출처를, 추정은 '추정' 을 붙인다.

## 1. 목표와 범위

| 넣는 것 | 빼는 것(이번 단계) |
|---|---|
| 등록된 장소로 이동 · 출발점 복귀 · 정지(취소) | 음성 입력(ASR) — 텍스트로 결정됨 |
| 한국어 자유 문장 → 고정 의도로 변환(온디바이스) | LLM 이 좌표 · 경로를 만드는 것 |
| 모르는 장소 · 애매한 문장 → **움직이지 않고** 되묻기 | 여러 단계 명령 연쇄(§8 결정 대기) |
| 장소 등록 · 수정(사람이 직접) | 지도에 없는 곳 탐색, 사람 따라가기 |

핵심 원칙 하나: **오인식의 결과가 '엉뚱한 곳으로 감' 이 아니라 '모른다 → 정지' 가 되게 한다.** 그래서 LLM 출력은 등록부에 있는 이름 하나 또는 정해진 동작 하나로만 끝나고, 실제 좌표는 사람이 등록한 표에서만 나온다(09-30 §9 제안 그대로).

## 3. 구조

```
[텍스트 입력]                       [Jetson 안]
 PC 터미널 / (선택) 웹 페이지  →  /rover/command (문장)
                                     │
                                     ▼
                            ① 의도 해석기 intent_node
                               ├ 규칙 기준선(별칭 사전 · 키워드)
                               └ LLM(llama.cpp, 문법 고정 JSON)
                                     │  {"action": go_to|return|stop|unknown, "place": 등록 이름|null}
                                     ▼
                            ② 검증 — 등록부에 있는 이름인가 · 지금 실행 가능한가
                                     │ (아니면 움직이지 않고 되묻기)
                                     ▼
                            ③ 장소 실행 노드 place_server
                               등록부(places.yaml) → map 자세 → 목표 여유 검사 → NavigateToPose
                                     │
                                     ▼
                            Nav2(지금 구성 그대로) · nav_guard · 펌웨어 워치독
```

### 3.1 장소 등록부 `places.yaml`
- 항목: `name`(대표 이름) · `aliases`(별칭 목록) · `x, y` (map) · `yaw_mode`(`p` 경로 끝 방향 | `f` 위치만 | 고정 각도) · `map`(office_v3 — 지도가 바뀌면 등록부 무효 표시) · `registered`(날짜 · 방법).
- 등록 방법: ⓐ 로버를 그 자리에 세우고 `register <이름>`(현재 map 자세 저장) ⓑ 좌표 직접 입력. 둘 다 사람이 한다 — LLM 은 등록부를 바꾸지 못함.
- 첫 등록 후보 = 이미 반복 검증된 no5 목표 자리(§8-1 에서 이름 정함): (0, 0) 출발점 · (2.25, −1.6) · (−1.6, −2.0) · (−1.65, −3.7) · (−1.6, −5.5) · (5.5, −2.2).
- 왜 yaml + 사람 등록: 좌표의 출처를 하나로(설명 가능성), LLM 환각이 좌표에 닿는 길을 원천 차단.

### 3.2 장소 실행 노드 `place_server`(rclpy)
- 서비스: `/place/go_to`(이름) · `/place/return` · `/place/stop` · `/place/list` · `/place/register`. 상태 토픽 `/place/status`(대기 · 이동 중 · 도착 · 실패 · 취소 + 이유).
- go_to 절차: 등록부 조회 → 목표 여유 검사(목표 차체 ↔ 치명 ≥ 0.10 m, 기존 `job377_goalclear` 기준) → `p` 이면 계획기로 경로 끝 방향 계산(러너 `path_end_yaw` 와 같은 식) → NavigateToPose → 결과를 상태로.
- 한 번에 목표 하나. 이동 중 새 go_to 는 '먼저 정지 · 취소 뒤' 로만(§8-4).
- 러너(job550)와 겹치는 코드(목표 방향 · 한도)는 공용 모듈로 빼서 두 곳이 같은 식을 쓰게 한다(지금 러너 동작은 바꾸지 않음).
- **LLM 없이 먼저 완성**(S1): 서비스만으로 실주행 검증 → LLM 은 그 앞단으로 붙인다.

### 3.3 의도 해석기 `intent_node`
- 출력 형식 하나로 고정: `{"action": "go_to"|"return"|"stop"|"unknown", "place": <등록 이름 또는 null>}`.
- **규칙 기준선**: 등록부 별칭 사전 + 동작 키워드('가', '이동', '돌아와', '멈춰' …) 매칭. LLM 의 가치는 이 기준선 대비 인식률 차이로만 주장한다.
- **LLM 경로**: llama.cpp(서버 모드)로 작은 지시형 모델 + **문법 고정 출력**(GBNF/JSON 스키마) — 형식이 깨질 수 없게. 프롬프트에 등록 이름 목록을 넣고 그 밖의 이름은 `unknown`.
- 검증 단계(②)가 마지막 방어: LLM 이 등록 밖 이름 · 형식 위반을 내면 `unknown` 으로 바꾸고 움직이지 않음.
- 정지 문장('멈춰', '그만', '스톱')은 **LLM 을 거치지 않는 빠른 길**로 먼저 처리(지연 · 오인식 둘 다 줄임).

### 3.4 입력 창구
- 1 차: PC 터미널에서 ssh 로 `rover_say "<문장>"`(Jetson 안 명령) — 새 구성 요소 없음.
- 2 차(**§8-3 결정 10-28: 만든다**): Jetson 이 띄우는 작은 웹 페이지(휴대폰 브라우저) — 현장에서 PC 없이 명령 · 정지. `scripts/place_web.py`: 장소 버튼(두 번 눌러 확인) · 정지(확인 없음) · 직접 입력 · 상태 · 배터리, 표준 라이브러리 HTTP 8080 · 접근 키(`~/.config/rover_web/key`, 저장소 밖). 휴대폰 정지는 보조 수단(Wi-Fi 의존).

## 4. 안전 설계
1. LLM 은 좌표를 만들지 않음 — 등록 이름 → 표의 좌표.
2. 모르는 장소 · 애매함 · 형식 위반 · 등록부 무효(지도 바뀜) → **움직이지 않음** + 이유 회신.
3. 정지는 Jetson 안 빠른 길(LLM 우회) + 기존 nav_guard · 펌웨어 워치독. PC 연결이 끊겨도 진행 중 목표는 nav_guard 한도로 끝남(2026-10-28 §3.1 교훈).
4. 이동 시작 전 목표 여유 검사 · prep 위치 검사(세션 시작 때)를 통과해야 함.
5. 사람 있는 환경은 이 단계 범위 밖(F3) — 운용 규칙 '사람 없음' 유지.

## 5. LLM 후보와 자원 예산 (모두 추정 — S4 에서 실측)
- 런타임: llama.cpp(CUDA 빌드, Jetson) — 단일 바이너리 · 문법 고정 출력 지원 · GGUF 4 bit 양자화. 대안 TensorRT-LLM 은 빌드 · 이식 부담이 커서 1 차에서 제외(기각 이유: 학습 대비 비용, JetPack 7.2 이전 때 다시 해야 함).
- 후보(크기 · 라이선스 · 한국어 성능은 받기 전에 확인): 1.5B~3B 급 다국어 지시형 모델 2~3 개 + 한국어 특화 소형 모델 1 개. 4 bit 기준 메모리 약 1~2.5 GB(추정).
- 예산(주행 중 측정값 기준 남는 몫, 추정): RAM 여유 약 4 GB(사용 3.2 / 7.6 GB) → 모델 ≤ 2.5 GB 목표. GPU 는 nvblox · cuVSLAM 과 나눠 씀(주행 중 90 % 56~64 %) → **추론은 이동 시작 전(정지 상태)에만** 하도록 해 주행 중 GPU 경쟁을 피한다. 주행 중엔 모델을 메모리에만 두고 추론하지 않음 — 이게 지켜지는지 S4 에서 확인.
- 왜 LLM 을 굳이 쓰나: 별칭 사전은 등록한 표현만 안다. 자유로운 한국어(조사 · 어순 · 존댓말 · 오타 · '아까 거기' 같은 지시어 일부)를 흡수하는지가 질문 — 기준선과 같은 문장 세트로 비교해 이득이 없으면 규칙 기준선으로 가는 것도 결과로 인정한다.

## 6. 평가(종료 조건 초안 — 각 시험 전에 수치 확정)

| 시험 | 무엇 | 지표 · 기준(초안) |
|---|---|---|
| T1 장소 이동 | 등록 장소마다 go_to → return | 성공 ≥ 9/10 per 장소 · 도착 오차 ≤ 0.25 m · 접촉 0 |
| T2 문장 세트 | 한국어 명령 문장 세트(장소 · 동작마다 바꿔 말하기 · 오타 · 존댓말/반말 · 모르는 장소 · 방해 문장) 약 100 문장, 정답 라벨 | 의도 + 장소 완전 일치율(기준선 대비) · **잘못된 장소로 가는 비율 = 0** · 모르는 장소 → unknown 비율 |
| T3 지연 | 문장 입력 → NavigateToPose 수락 | p50 ≤ 2 s · p95 ≤ 4 s(정지 빠른 길 ≤ 0.5 s) |
| T4 자원 · 간섭 | 모델 상주 상태로 no5 순회 | RAM 여유 ≥ 1 GB · nvblox ≥ 9 Hz · TF 실패 0 · Control loop missed 기준선(43~84 / 7 분) 이내 |
| T5 통합 | 문장만으로 장소 3 곳 들렀다 복귀 | 8/8 류 판정 + T2 · T3 기준 동시 충족 |

T2 는 PC 에서도 같은 GGUF · 같은 설정(온도 0)으로 돌릴 수 있어 정확도 비교를 먼저 하고, 지연 · 자원(T3 · T4)은 Jetson 에서만 잰다.

|---|---|---|---|

## 8. 결정이 필요한 것(사용자)
1. **장소 이름 · 별칭** — §3.1 후보 자리에 붙일 실제 이름(예: 사무실에서 부르는 이름). 몇 곳까지(첫 판 4~6 곳 권장).
2. **'돌아와' 의 뜻** — 출발 테이프(0, 0) 고정인지, '직전 장소' 인지.
3. **입력 창구** — ~~PC 터미널만(1 차) / 휴대폰 웹 페이지도(현장 정지 수단 겸).~~ → **결정(2026-10-28 사용자): 휴대폰 웹 페이지도 만든다.** 구현 `scripts/place_web.py`(debug_log 10-28 §16).
4. **이동 중 새 명령** — 무시 · 현재 취소 후 새 목표 · 되묻기 중 무엇.
5. **여러 단계 명령**('B 들렀다가 돌아와') — 이번 범위에 넣을지.
6. **모델 라이선스 조건** — 개인 · 연구용 한정 라이선스 모델도 후보에 넣을지(공개 저장소에는 가중치를 넣지 않음).

## 9. 위험과 대응
| 위험 | 대응 |
|---|---|
| 작은 모델의 한국어 이해 부족 | 문법 고정 + 등록 이름 목록 제시 + 규칙 기준선과 비교 — 이득 없으면 기준선 채택도 결과 |
| 메모리 부족 · GPU 경쟁으로 주행 품질 저하 | 추론은 정지 상태에서만, T4 로 확인, 모델 크기 상한 2.5 GB |
| 등록 좌표가 지도 갱신 뒤 어긋남 | 등록부에 지도 이름 기록, 지도 바뀌면 무효 → 재등록 |
| 좁은 곳 장소(통로 남쪽 등)의 계획 불안정 | 첫 판 등록은 넓은 곳 우선, 좁은 곳은 `f`(위치만) |
| PC 연결 끊김 | 정지 빠른 길 · nav_guard 를 Jetson 안에 |

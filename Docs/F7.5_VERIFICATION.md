# F7.5 — AK09916 자기계 + `/imu/mag` 발행

| 항목 | 값 |
|---|---|
| 문서 ID | ROVER-FW-011b |
| 단계 | F7.5 (펌웨어 개발 10단계 후 mag 보강) |
| 목적 | ICM-20948 패키지 내장 AK09916 활성 + `sensor_msgs/MagneticField` 발행 |
| 전제 | F7 완료 (`/imu/data_raw` 정상 발행) |
| 폐기됨 | 외장 RM3100 (보드 미실장 — `board_rm3100_missing` 메모리) |

---

## 1. 배경 — 왜 RM3100 이 아니라 AK09916 인가

ALOPS Jupiter R1.4 dev 보드에 외장 RM3100 IC 가 **미실장**. 양산 단계에서
재실장 또는 산업급 자기계 교체 검토 중이지만 dev 단계에서는 패키지 내장
AK09916 (ICM-20948 의 두 번째 die) 으로 대체.

```
[STM32 SPI2] ──→ [ICM-20948 (I2C master)] ──AUX I2C──→ [AK09916 die]
                                                 (0x0C, 16-bit LE, ±4912 µT)
```

호스트(STM32) 는 SPI2 만 사용. AK09916 액세스는 ICM-20948 이 대행. STM32
의 I2C1 (원래 RM3100 용) 은 **현재 미사용**.

## 2. 추가/변경 사항

### 2.1 [`App/drivers/icm20948_driver.{h,c}`](../firmware/rover_jupiter_fw/App/drivers/) — Cold-boot recovery + AUX I2C master 헬퍼

**Cold-boot recovery in `imu_init()`** (sandbox 검증, 누락 시 WHOAMI=0x00):
1. CS HIGH + `HAL_Delay(100)` — VDD ramp 안정화
2. **MISO pull-up** (PB14 + `GPIO_PULLUP`) — silent slave vs chip-driven 구분
3. **CS strobe** — LOW 1ms → HIGH 1ms — cold-boot 시 SPI 모드 lock
4. **첫 SPI byte discard** — garbage 버림
5. DEVICE_RESET → 100ms → wake → 35ms → I2C_IF_DIS → WHO_AM_I 검증 → bank2 config

**Bank 캐시** (`s_current_bank`): 같은 bank 반복 선택 SPI 트래픽 절약. DEVICE_RESET
후 `0xFF` 로 무효화 (chip 내부 bank latch 도 0 으로 reset 됨).

**AUX I2C master 헬퍼** (SLV4 미사용 — SLV0 만으로 단순화):

| 함수 | 용도 |
|---|---|
| `icm20948_i2c_master_enable()`         | USER_CTRL=I2C_MST_EN\|I2C_IF_DIS + I2C_MST_CTRL=0x07 (400kHz) |
| `icm20948_aux_slv0_write_byte()`       | SLV0 one-shot write + delay + **CTRL=0 disable** |
| `icm20948_aux_slv0_read_byte()`        | SLV0 one-shot read + delay + read EXT_SLV_SENS_00 + disable |
| `icm20948_aux_setup_slave0_read()`     | SLV0 streaming arm (EN 유지) — ICM ODR 마다 자동 read |
| `icm20948_aux_read_ext_sens(buf,len)`  | EXT_SLV_SENS_DATA_00 burst read |
| `icm20948_debug_read(bank,reg,val)`    | 브링업 진단 전용 |

**SLV0 one-shot 후 disable 필수**: 안 하면 ICM 가 매 ODR cycle 마다 같은
transaction 반복 → 다음 reconfigure 시 transient 상태에서 잘못된 transaction.

### 2.2 [`App/drivers/ak09916_driver.{h,c}`](../firmware/rover_jupiter_fw/App/drivers/) — 신규
`i_magnetometer.h` 구현. RM3100 드라이버 (`rm3100_driver.{c,h}`) 는 **삭제**.

`mag_init()` 순서 (sandbox 검증):
1. `icm20948_i2c_master_enable()` — ICM I2C master 활성
2. SLV0 write CNTL3=0x01 (soft reset) → 100ms 대기
3. SLV0 read WIA2 검증 (=0x09)
4. SLV0 write CNTL2=0x08 (continuous mode 4, **100 Hz**)
5. SLV0 streaming arm: HXL(0x11) 부터 8바이트 자동 read 매 ODR cycle
   - 결과 적재: HXL HXH HYL HYH HZL HZH dummy ST2
   - **데이터는 little-endian** (ICM accel/gyro BE 와 반대)
   - ST2 포함이라 매 cycle AK09916 측정 자동 unlock

`mag_read()`: EXT_SLV_SENS_DATA_00 (Bank 0, 0x3B) 부터 8바이트 burst →
LE int16 파싱 → MagSample.mag_raw[] (int32_t 로 sign-extend).

### 2.3 [`App/app/imu_processor.{h,c}`](../firmware/rover_jupiter_fw/App/app/) — mag 처리 추가
- `MagSi` 구조체 (mx/my/mz Tesla + ts_ms + valid)
- `imu_processor_init()` — `imu_init()` + `imu_read_whoami()` + `mag_init()` 순차 호출
- `imu_processor_update()` — IMU burst 후 mag_read() 폴링 (100Hz, init 실패 시 skip)
- `imu_processor_get_mag()` — 최신 mag 스냅샷
- `imu_processor_imu_ready()` / `imu_processor_get_whoami()` / `imu_processor_mag_ready()` — status getter
- 변환: 0.15 µT/LSB → 1.5e-7 T/LSB

### 2.4 [`Core/Src/main.c`](../firmware/rover_jupiter_fw/Core/Src/main.c) — init 위치 이동
**`imu_processor_init()` 을 scheduler 시작 전 USER CODE BEGIN 2 에서 호출.**
이전엔 control task 안에서 호출했으나 다음 문제로 이동:
- f1_sanity (BelowNormal) 와 control task (AboveNormal) 사이 SPI race
- DEVICE_RESET 진행 중 다른 task 의 register write 가 default 로 되돌아감
- Cold-boot recovery 가 task context 의 HAL_Delay/yield 와 충돌

main.c bare-metal 단계에서 호출 시 task 가 아직 없으므로 race 차단 + 안정적 cold-boot.

### 2.5 [`App/app/f1_sanity_task.c`](../firmware/rover_jupiter_fw/App/app/)
- `imu_init`/`mag_init`/`imu_read_whoami` 호출 **제거** — getter (`imu_processor_imu_ready` 등) 만 사용
- f1_sanity 는 SPI 자체를 만지지 않음 (모터·엔코더·I2C·ADC 만)
- 출력: `imu=READY(whoami=0xEA) mag=READY` (정상) / `FAIL` (init 실패)

### 2.5 [`App/microros/microros_task.c`](../firmware/rover_jupiter_fw/App/microros/)
- `/imu/mag` (`sensor_msgs/MagneticField`) publisher 추가
- frame_id="imu_link" (IMU 와 동일)
- spin loop 매 cycle 발행 (~29 Hz) — AK09916 측정 50Hz 보다 낮아 데이터 신선
- `magnetic_field_covariance` = 0 (unknown) — Jetson 측 yaml 에서 override

### 2.6 RAM·Flash 변화 (실측)
| 영역 | F7/F8 | F7.5 | 증가 |
|---|---|---|---|
| Flash (text) | ~106 KB | **117 KB** | +11 KB |
| RAM (data+bss) | ~100 KB | **~98 KB** | -2 KB (RM3100 storage 제거) |

> 빌드 사이즈 `arm-none-eabi-size`:
> `text=119360, data=5008, bss=95216` → Flash 117 KB / RAM 98 KB.

## 3. 검증 절차

### 3.1 부팅 콘솔 (UART5 115200)
```
[F1-init] motor=OK enc=OK imu=OK(whoami=0xEA) mag=READY adc=OK(raw=...)
```
- `mag=READY` → control task 의 imu_processor_init() 안에서 AK09916 식별·init 성공
- `mag=FAIL` → init 실패 (ICM I2C master 미동작 또는 AK09916 응답 없음).
  더 자세한 진단은 [`microros_task.c`](../firmware/rover_jupiter_fw/App/microros/microros_task.c)
  에 mag init 로그 추가 검토

### 3.2 토픽 확인
```bash
ros2 topic list
# 기대: /imu/mag 추가

ros2 topic info /imu/mag
# Type: sensor_msgs/msg/MagneticField

ros2 topic hz /imu/mag
# 기대: ~25~30 Hz (spin loop 와 동일)

ros2 topic echo --once /imu/mag
```
기대값 (정지·실내, 한국 지자기 약 30~50 µT):
- `magnetic_field`: x/y/z 합성 magnitude **2e-5 ~ 6e-5 T** (=20~60 µT)
- 한 축이 dominantly 큼 (북쪽 방향)
- `header.frame_id`: "imu_link"
- `header.stamp`: 0 아닌 값

### 3.3 동적 검증 — 자기 북쪽 매핑
보드를 **수평 유지하며 천천히 360° 회전**:
```bash
ros2 topic echo /imu/mag --field magnetic_field
```
- x, y 가 sinusoidal 변화 (한 주기 = 1 회전)
- z 는 거의 일정 (지자기 수직 성분, 한국 약 +35 µT 또는 -35 µT, 보드 mount 에 따라)

→ 차체 좌표계 (REP-103) 와 정합 매핑 결정:
- z 축 = 중력 반대 방향 (F7 에서 확정)
- xy 평면 회전 시 x/y 가 (cosθ, sinθ) 형태 → 북쪽 방향 결정

### 3.4 체크 항목

| # | 항목 | 통과 조건 |
|---|---|---|
| 1 | F1-init `mag=OK(id=0x48)` | WIA1=0x48 |
| 2 | `/imu/mag` 토픽 발견 | `ros2 topic list` |
| 3 | 발행률 | `ros2 topic hz` ≈ 25~30 Hz |
| 4 | 지자기 magnitude | sqrt(x²+y²+z²) ∈ [2e-5, 6e-5] T |
| 5 | 회전 응답 | 수평 회전 시 xy 가 sinusoidal |
| 6 | F7 IMU 유지 | `/imu/data_raw` 정상, 발행률 변동 < 10% |
| 7 | F8 watchdog/status 유지 | `/rover/status` OK, cmd_vel 동작 |
| 8 | freeHeap 변동 | F8 대비 -1~+1 KB (정상) |

### 3.5 RViz 시각화 (선택)
- RViz2 에 `MagneticField` display 가 없으므로 plotjuggler 또는 `ros2 topic echo` 권장
- 또는 `rqt_plot /imu/mag/magnetic_field/x:y:z` 로 회전 시 sinusoidal 관찰

## 4. Axis 매핑 — AK09916 vs ICM accel/gyro

AK09916 의 X/Y/Z 가 ICM accel/gyro 의 X/Y/Z 와 **다를 수 있음** (datasheet
§5: AK09916 X = ICM Y, AK09916 Y = ICM X, AK09916 Z = -ICM Z 가능).

§3.3 회전 실험으로 매핑 확인 후 필요시 `imu_processor.c` 에서 swap·sign flip.
일단 raw 그대로 발행하고 Jetson 측 `robot_localization` yaml 또는
`imu_transformer` 노드에서 보정도 가능.

## 5. 알려진 한계

- **Hard-iron / soft-iron 보정 없음**: 실내 금속/모터 영향 큼. Jetson 측
  `magnetometer_calibration` 또는 수동 ellipsoid fit 필요 (Phase 2).
- **온도 보상 없음**: AK09916 자체 온도 드리프트 미보정.
- **Covariance 0**: ROS EKF 노드 사용 시 yaml 에서 명시 설정 필요
  (typical: diag(1e-12) T² ≈ 1 µT std).
- **I2C master 점유**: ICM AUX bus 가 AK09916 전용 — 다른 AUX 디바이스 추가 시
  slave 1~3 사용 또는 slave 0 read 길이 확장 필요.
- **양산기**: 산업급 magnetometer (HMC5983, MMC5983MA 등) 로 교체 검토.

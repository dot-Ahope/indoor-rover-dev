## §2 그럼 1.1 cm 는 어디서 — 계획 경로 대 실제 지나간 길 (`jobs/anal_track_dev.py` → `outputs/anal_track_dev_f2pi1.txt` · `_f2sm3.txt` · `anal_track_dev_f2pi1_freeze.txt`)

- f2sm3(같은 구성, 실제 여유 최소 9.1 cm)는 최신 경로 여유 9.5~12 cm 를 거의 그대로 따라감(벗어남 −2~+3 cm).
- 결론(측정 + 추론): f2pi1 의 1.1 cm 는 **계획기가 붙인 게 아니라, 컨트롤러(MPPI)가 상자 옆에서 경로보다 상자 쪽으로 약 10 cm 안쪽(목표 (0, 0) 쪽 대각선)으로 질러간 것** + 경로가 그 자리에서 다시 그려져 질러간 길을 따라감. 그때 로컬 코스트맵의 상자는 실제보다 약 3 cm 남쪽(§10-22 §16) → MPPI 에겐 5.6 cm 여유로 보여 질러가도 비용이 작았음(추정). f2sm3 에서 안 질러간 이유는 미확인(접근 각도 · 기억 위치 차 후보).
- 사용자 제안(노랑 쪽을 따르게)에 대한 답: 방향은 맞으나 **손잡이는 전역 감쇠가 아니라 MPPI 쪽**. 후보(정하지 않음):
  1. MPPI 경로 따르기 강화 — PathAlignCritic `max_path_occupancy_ratio 0.05`(경로점 5 % 넘게 비용 칸이면 이 크리틱이 꺼짐 — 상자 옆에서 꺼졌는지 미확인) · PathFollow/PathAlign 가중.
  2. 로컬 inflation(0.40 / 2.5) 을 노랑 띠가 넓게 — CostCritic 이 보는 비용을 상자 둘레에서 키움(10-13 의 cost_weight 3 배와 달리 '먼 곳 비용' 만 키움). 효과 방향 미확인.
  3. CostCritic cost_weight — 10-13 에 3 배는 좁은 곳 머뭇거림으로 되돌림.
  4. 근본: 기억 오차(오도메트리) — f2sm4 → vslam:=on.

### §20.7 only_new 오프라인 시험 — bag 재생으로 막힘 판정 재현 (사용자: "f2rp3 bag 재생으로 오프라인 시험 진행하라")
- 방법(`jobs/anal_pba_replay.py`): C++ 노드 판정을 파이썬으로 그대로 옮겨 기록된 입력으로 50 Hz 판정 — 경로 = BT 가 실제로 준 {path}(nav2 로그 'Received a path to smooth' 마다 스무딩 성공 → `/plan_smoothed`, 실패 → 직전 `/plan` 원경로), 지도 = bag `/global_costmap/costmap`(≈ 1.5 s 간격, 290 장), 로버 = `/tf`. 인자는 BT xml 값. ⚠ 시험한 것은 판정 논리이고 C++ 코드 자체(.so)는 아님 — C++ 판은 f2rp4 에서 상자 막힘 1 번을 실제로 냈다(§20.5)는 데까지만 확인.

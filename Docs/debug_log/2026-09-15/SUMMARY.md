## 2. mp1 — MPPI 첫 주행 (Smac BT, 목표 상자 뒤 1.8/0, 패딩 0.01): ABORTED 48 s — 컨트롤러가 아니라 **계획기 재계획 실패**

배치: 로버를 20 cm 우측 평행 이동 후 상자 1.14/+0.02(가장자리 +0.11), 좌측 가구 셀 **+0.55**. 게이트: 코스 띠 근거 없는 셀 3 → 60 s 뒤 1 → 통과, 창 0.231.
주행 중 사용자 정지 요청("사람이 앞에 있다") — 그 시점엔 이미 ABORTED 로 정지 상태였고 0 속도 명령을 추가 송신, 휠 odom 0.0 확인. 절차: 시야 안에 사람이 들어오면 즉시 정지 명령(job156).

| 구간 | 값 |
|---|---|
| 진입 (t 2~20) | v **0.04~0.05**(RPP 0.080), w 0.03~0.05 로 **부드러운 차선 변경** 횡 0 → +0.40, 부호반전 0, 충돌감지 0, 실여유 최소 **0.20 m**(RPP 주행은 0.03~0.10) |
| 정체 (t 20~48) | (0.79, +0.40)에서 v → 0. nav2.log: **"SmacHybrid: failed to create plan, no valid path found" ×15** → 클리어·재계획 반복 → BackUp(−0.05) 2회 → Goal failed |
| 경고 | Behavior Tree tick rate exceeded ×3 (MPPI 1000×32 @20 Hz CPU 부하) |

기전: MPPI 는 상자(깊이 셀 다수)와 좌측 가구(라이다 셀 소수) 사이에서 **좌측으로 치우쳐**(+0.40; 기하 중앙 +0.33) 지나갔고, 그 자세에서 패딩 footprint 좌측 가장자리 +0.575 가
좌측 가구 LETHAL 셀(+0.55, 셀 0.525~0.575)과 겹친다. BT 는 1 Hz 로 재계획하는데 **Smac Hybrid-A* 는 시작 footprint 가 LETHAL 에 닿으면 계획을 거부**한다(NavFn 은 시작 셀만 본다).
→ 계획 실패 → 복구 → 실패 → ABORT. 즉 오늘 실패는 MPPI 의 회피 자체가 아니라 **"Smac + 좁은 띠(유효 중심 폭 ≈6 cm) + 1 Hz 재계획"** 의 조합이다.
MPPI 가 보여 준 것: 정지 없이(둘레 검사 없음) 부드럽게(부호반전 0), 여유 0.20 m 를 두고 지나간다 — 사용자가 원한 "자연스러운 이동" 의 형태. 대가: 속도 0.05(장애물 비용 감속), CPU.

다음 변수(하나): **BT planner_id → GridBased(NavFn) + MPPI 유지.** NavFn 은 inflation 띠 안에서도 재계획이 되고, 곡률 완화는 MPPI 가 국소적으로 맡는다.
그 뒤 MPPI 속도(ObstaclesCritic repulsion/critical, vx_max 0.08 유지)·CPU(batch 1000 → 600, controller_frequency 20 → 15) 를 측정으로 조정.

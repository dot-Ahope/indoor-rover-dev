이 페이지는 2026-11-04 에 그날의 SUMMARY.md를 원천으로 다시 만든 것입니다. 오전에는 전날 찾은 휠 스케일 보정 VX_SCALE=0.783 을 줄자로 검증했고, 회전을 포함한 드리프트와 좌우 트랙 비대칭을 쟀습니다. 오후에는 rover_navigation 패키지를 새로 만들어 Nav2 로 첫 자율주행에 성공했습니다. 이어 180° 회전 목표에서 로버가 꼼짝 않던 데드락을 풀었습니다. 좁은 곳 벤치마크(RPP · MPPI)는 전부 실패했고, 공통 원인을 '기동 데드밴드' 로 보고 펌웨어 보상 코드를 썼습니다. 뒤 기록과 문제 대장이 바로잡은 곳 6 건은 원문을 그대로 두고 11-04 정정 표시를 붙였습니다.

180° 회전 목표에서 꼼짝 않음 — 데드락B-1

본 것1 차: 목표 수락 뒤 약 100 s 정지, 그 뒤 회전 — 회전시킨 것은 컨트롤러가 아니라 spin 복구. 진행 검사기 SimpleProgressChecker 는 병진만 진행으로 인정 → PoseProgressChecker(+ required_movement_angle 0.5)로 바꿨지만 정지는 그대로. 추론/cmd_vel_nav(RPP)와 /cmd_vel(스무더)을 같이 보니 둘 다 w = 0.05 rad/s 를 68 s 내내 냄, heading 176.9 → 176.4°. RPP rotateToHeading() 은 각속도를 '현재 측정 속도 ± max_angular_accel × dt' 로 클램프 → 1.0 × 0.05 = 첫 명령 상한 0.05 rad/s = 바퀴 ±6 mm/s → "정지마찰 · PWM 데드밴드 이하라 안 움직임" → 측정 속도 0 → 다음 주기도 0.05 → 영구 데드락. 직진이 됐던 이유: RPP 는 선속도엔 이 클램프를 안 건다.(11-04 정정: 직접 원인은 기계가 아니라 펌웨어였다 — 같은 펌웨어의 speed_controller.c TARGET_THRESH 0.01 m/s 미만 목표는 '정지 명령' 으로 처리돼, 6 mm/s 명령은 목표 0 · duty 0 이 된다(코드 읽기 + 09-17 mp8 실측). 기계적 기동 문턱(09-03 스윕 0.012~0.016)은 그 위의 두 번째 층 — Docs/issues/start-deadband.md §5 실수 ①) 결론max_angular_accel 1.0 → 4.0(첫 명령 0.2 rad/s). 수정 뒤 t = 2 s 에 w +0.243 으로 즉시 회전 → SUCCEEDED, 실제 회전 +178.8°(오차 1.2°), 위치 오차 14.8 cm, 약 28 s. 교훈(원문): 측정 속도 기반 램프업은 '이미 움직이는 로봇' 을 가정한다 — 첫 명령이 기동 임계를 넘도록 가속 한계를 잡아야 한다. 스크립트 핵심

static float apply_min_wheel_speed(float v)
{
    if (fabsf(v) < WHEEL_SPEED_EPS_MPS) return 0.0f;
    if (fabsf(v) < MIN_WHEEL_SPEED_MPS) return copysignf(MIN_WHEEL_SPEED_MPS, v);

}

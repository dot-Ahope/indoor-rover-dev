## 5. 판단
- **확정된 것(배제)**: 공유기 재부팅, MAC 필터, 접속 수 제한, Easy Mesh, WAN 장애, Jetson 드라이버 오류·약신호·트래픽·SSH 빈도(09-17 §17.3).
- **남은 후보(미확정)**:
  1. **DFS**: 160 MHz 가 DFS 채널 52~64 를 포함 → 레이더(또는 오감지) 시 AP 가 그 채널을 비워야 하고, 일부 펌웨어는 CSA 없이 무선부를 재구성해 단말을 끊는다 — **끊김(reason 2)** 을 설명할 수 있다. 하지만 이후 수 분~수 시간 이어진 **재인증 거부**는 설명하지 못한다.
  2. **PMF(802.11w) + rtl88x2ce 외부 드라이버**: 끊긴 뒤 AP 가 옛 보안 연관을 쥐고 있거나 드라이버가 보호 관리 프레임을 잘못 처리하면 4-way handshake 가 실패한다 — **재인증 거부**를 설명할 수 있다. 하지만 **첫 끊김**의 원인은 아니다.
  3. AP 펌웨어(15.03.0) 결함.
  → 두 현상(끊김·재인증 거부)이 서로 다른 원인일 수 있다. 세 사건만으로는 가를 수 없다.

### 15.3 컨트롤러가 왜 여유를 더 벌리지 않나 — ObstaclesCritic 은 17.5 cm 안에서 거리를 구분하지 못한다
- 설치 버전 `ros-humble-nav2-mppi-controller 1.1.20`(`outputs/j447_mppi_ver.txt`), 같은 태그 소스(`obstacles_critic.cpp`, `cost_critic.cpp`, README) 확인:
  1. `consider_footprint: true` 이고 로버 중심 비용 ≥ 외접 비용(로컬 0.40/2.5 에서 ≈178, 중심↔장애물 0.313 m 이내)이면 **차체 둘레 최대 비용**을 쓴다. 둘레 셀이 장애물에서 내접 반경 0.175 m 안이면 그 값은 항상 253(INSCRIBED) → `distanceToObstacle` = 0.175 로 고정 → 옆 여유 1 cm 든 14 cm 든 같은 비용. 1.1.20 CostCritic 소스 주석도 같은 말을 한다: "footprintCostAtPose will always return INSCRIBED if footprint is over it".
  2. 1.1.20 의 ObstaclesCritic 은 거리 역산에 쓰는 `cost_scaling_factor`·`inflation_radius` 를 **코스트맵이 아니라 크리틱 자기 파라미터**에서 읽는다(README: "This should be the same as for your inflation layer (Humble only)"). 우리 YAML 에는 없어 기본 10.0/0.55 — 로컬 코스트맵 2.5/0.40 과 다르다(설정 누락).
  3. 정적 계산(`jobs/job449_criticcurve.py` → `outputs/j449_criticcurve.txt`, 1.1.20 식 그대로, 통로 0.55·0.60): 현재 설정·값 맞춤·`collision_margin_distance` 0.10 모두 옆 여유 1~25 cm 에서 **비용이 일정**. → 지금 ObstaclesCritic 은 LETHAL 접촉 검사 역할만 하고, 옆 위치는 경로 크리틱(PathAlign 14 + PathFollow 10)이 정한다. **09-17 메모의 'inflation = 여유 선호' 는 MPPI 컨트롤러에는 해당하지 않았다**(전역 계획에는 해당).
  4. CostCritic(1.1.20 에 있음, README 예시 설정이 ObstaclesCritic 대신 이것을 쓴다)은 충돌은 차체로 검사하고 점수는 **중심 비용**으로 매겨 기울기가 있다. 그러나 기본 가중 3.81 의 기울기(≈0.08 /cm)는 경로 크리틱(≈0.24 /cm)보다 작아, 정적 근사로는 경로가 5 cm 로 붙으면 컨트롤러도 5 cm 에 머문다(가중 12 이상에서야 통로 중앙으로 — 그러면 모든 곳에서 경로 추종보다 장애물이 우세).
- 결론: 여유를 정하는 것은 **전역 원경로의 옆 위치**이고, 컨트롤러는 그것을 거의 그대로 따른다. 고칠 1 순위는 계획, 컨트롤러 크리틱 교체는 2 순위(정확성 수정·모서리 안쪽 붙음 대응).

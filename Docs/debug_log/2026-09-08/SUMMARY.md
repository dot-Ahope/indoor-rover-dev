- **통로가 실제로 막혀 있음.** 우측 여유 6cm(편측 3cm)는 회전 오도 ±15% 인 스키드스티어에 비현실적. 좌측은 물체 때문에 음수.
- 따라서 **inflation 을 더 낮춰도 통과 불가** — 막는 것은 비용 경사가 아니라 내접반경(경성 풋프린트). 09-08 첫 분석의 "슬롯 0.04/0.10m" 도, 그 정정판의 "우측 0.24m" 도 상자 폭을 10cm 로 가정한 오류였음. 실측 폭 0.30m 기준이 맞다.
- inflation 0.22 변경 자체는 유지(향후 좁은 통로용으로 유효). 이번 코스는 상자 재배치 또는 넓은 공간이 필요.

## 정정·원복: inflation 은 통과 가능/불가를 정하지 않는다
사용자 질문("인플레이션이 차량 크기까지 포함하여 적용되는 것이었나?") — **맞다.**
- Nav2 인플레이션 레이어 비용 구조: 장애물 셀 = LETHAL(254) / **내접반경 이내 = INSCRIBED_INFLATED(253)** → 플래너·컨트롤러가 충돌로 취급(경성 차단) / 내접반경 ~ `inflation_radius` = 252→0 감쇠하는 **소프트 비용**(통과 가능, 비용만 큼).
- 내접반경 = 반폭 0.165 + `footprint_padding` 0.05 = **0.215**, 즉 차체 크기에서 나온다. `inflation_radius` 는 그 바깥의 비용 경사 범위일 뿐.
- → 좁은 길 통과를 좌우하는 것은 **패딩(내접반경)**, inflation 이 아니다. 09-08 저녁 0.22 하향은 통과 여부를 바꾸지 못했고(막은 것은 상자 폭 0.30m + 통로 1.37m 기하), 중앙 선호만 잃었다.
- **원복: local `inflation_radius` 0.35 / `cost_scaling_factor` 2.5, global 0.25 / 3.0.** 좁은 길에서는 RPP 의 cost-regulated 감속으로 느려질 뿐 통과는 가능하며, 그 대가로 통로 중앙 선호(벽 접촉 예방)를 얻는다.
- 향후 진짜 좁은 길이 필요하면 조정 대상은 `footprint_padding`(0.05 → ?) — 라이다 0.2m 사각 안전과의 트레이드오프이므로 근접 실측 후 결정.

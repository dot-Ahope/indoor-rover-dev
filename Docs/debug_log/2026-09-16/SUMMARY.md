### 1.3 원인 — MPPI 지평 0.13 m 에서는 경로 크리틱이 켜지지 않는다 (검증된 것 / 추론한 것 구분)

**검증(계측)**
1. 왼쪽으로 간 것 자체는 계획이다: NavFn 경로가 s=0.5 m 에서 +39° 사선으로 통로(y +0.44, 창 0.235 m 의 중앙)로 들어간다. t 5~17 에 로버는 그 경로를 횡편차 ≤ 2 cm 로 따랐다.
2. 이상은 **t 18~20 의 제자리 좌회전**이다. 그 순간 경로는 −0.5~−14°(오른쪽)를 요구했고 로버는 +15° 왼쪽으로 돌았다.
3. 그 순간의 코스트맵 헤딩별 비용(job327 t=18): 앞-왼쪽(+10°, +20°)으로 0.15 m 전진 = 89/96, 정면 = 96, 앞-오른쪽(−10°, −20°) = **99(내접)**. 오른쪽 앞 0.23 m 에 상자 앞면 LETHAL. 즉 **코스트맵 기울기는 왼쪽을 가리켰다**.
4. 정체 중 nav2.log 에 `Optimizer fail`·collision 없음 → "모든 샘플 충돌" 이 아니다. 진행 실패(PoseProgressChecker 0.25 m/0.5 rad/25 s)가 2 회 걸렸고 복구(ClearCostmapExceptRegion)는 컨트롤러 평형을 바꾸지 못했다.
5. 재계획된 직진 경로(상대 −58°)에서도 회전이 없었다 → 경로 모양이 아니라 **컨트롤러가 큰 heading 오차를 못 푼다**.

**추론(Humble MPPI 크리틱 소스 의미론, 내부값은 `visualize: false` 라 미기록)**
- 지평 = time_steps 32 × model_dt 0.05 = 1.6 s → 0.08 m/s 에서 **0.128 m**. Nav2 기본(56 step, 0.5 m/s 로봇)은 1.4 m.
- PathAlign/PathAngle/PathFollow 는 "샘플 궤적 끝이 도달한 경로 점 index(furthest_reached)" 로 동작한다. 경로 점간격 0.026~0.047 m 이므로 index ≤ 5.
  - **PathAlignCritic(가중 14)** 은 `offset_from_furthest: 20` 미만이면 return → **이 로버에서는 한 번도 켜진 적이 없다.**
  - **PathAngleCritic(가중 2)** 는 목표점 방위 오차 > `max_angle_to_furthest 1.0 rad(57°)` 일 때만 → 정체 중 오차 44~62° 라 간헐 작동.
  - 남는 힘은 **PathFollowCritic(5)** 뿐 = 0.25~0.4 m 앞 점으로 당기는 pure-pursuit. 완만한 곡선은 따르지만(t 5~17), 장애물 기울기(ObstaclesCritic repulsion, 상자 앞면 0.23 m)를 이기지 못해 왼쪽으로 틀었고(t 18~20), 오차가 커진 뒤엔 제자리 회전을 보상할 크리틱이 없어 떨림 평형에 빠졌다.
- mp1(09-15, Smac+MPPI) 의 "좌측 치우침 +0.40" 도 같은 기제로 설명된다.

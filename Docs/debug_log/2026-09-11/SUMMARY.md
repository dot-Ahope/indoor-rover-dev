# 2026-09-11 — 장애물이 사라진 진짜 이유: Nav2 가 멈춰야 할 이유를 지우고 있었다

## 0. 이 날의 결론

09-10 의 미해결 과제("로컬 코스트맵이 깊이 소실 1.3초 만에 상자를 통째로 버린다")를 규명했다.
**범인은 STVL 이 아니라 Nav2 의 behavior tree 였다.**

```
[ERROR] RegulatedPurePursuitController detected collision ahead!
[INFO]  Received request to clear entirely the local_costmap      <- 17 ms 후
```

RPP 가 충돌을 감지하면 BT 의 `ClearEntireCostmap` 이 로컬 코스트맵을 통째로 지운다.
장애물이 사라지니 다시 갈 수 있게 되고, 그대로 부딪힌다.
**멈춰야 할 이유를 지우고 다시 가는 것**이다.

내가 세운 세 가설(감쇠 / 절두체 clearing / 화각 이탈)은 **전부 틀렸다.**
통제 실험이 하나씩 지웠고, 남은 차이 하나가 답이었다.

## 3. 고침 — ClearEntireCostmap → ClearCostmapExceptRegion

`config/nav_to_pose_no_spin.xml` 의 Clear 노드 4개를 전부 교체했다.
전체 삭제 대신 **로봇 주변 `reset_distance` 안을 보존하고 바깥만** 지운다.

```
로컬  reset_distance 1.2 m   (로컬은 3x3m = 반경 1.5m 이므로 바깥 링만)
전역  reset_distance 2.0 m   (멀리 있는 유령은 여전히 정리됨)
```

기각한 대안:
- Clear 노드 제거 → RecoveryNode 구조가 무너져 실패가 곧장 상위로 전파된다.
- RPP `max_allowed_time_to_collision_up_to_carrot` 축소 → 충돌 감지를 늦춰 증상만 가린다.
  안전 여유를 줄이는 방향이라 근본과 반대다.

**"상자를 치고 지나감" 은 사라졌다.**

## 4. 감쇠 되돌림 — 09-10 의 결정을 취소한다

로컬 `decay_model: -1`(영속) → **0 (선형 30초)**.

09-10 에 영속으로 바꾼 근거는 "감쇠가 상자를 녹인다" 였는데, **진짜 원인이 BT 로 확정되면서
그 근거가 무효가 됐다.** 영속은 이제 이득 없이 대가만 남는다 — 한 번 잘못 찍힌 복셀을
지울 수단이 사라진다:

- 절두체 clearing 은 `min_z: 0.55` 라 근거리를 못 지운다
- 라이다 레이캐스팅은 `combination_method: 1`(Maximum) 때문에 STVL 값을 못 이긴다

30.0 은 09-09 job167 에서 근거를 갖고 정한 값이라 그대로 복원했다.

## 5. 남은 문제 — 계획이 장애물에 붙는다

job231 은 접촉은 없었지만 **완주하지 못했다**(ABORTED, 1.05 m).
전진 → 충돌 감지 → BackUp → 재시도를 반복했다(`detected collision` 14건).

```
② 계획의 최소 여유  2.6 cm     <- RPP 는 footprint+padding(반폭 0.215)으로 검사한다
```

코스트맵 격자(`job230_map.py`)로 본 환경:

```
        y=+0.8 ......... 0 ......... -0.8
  x=+0.45 I+++++++++++++++++++++++++++IIIII
  x=+0.25 IIIIIIII++++...........++++IIIIXX  <- 차체 앞끝
  x=-0.25 IIXXIIII++++........++++IIIIXXIII  <- 차체 뒤끝
```

**차체 중심이 다닐 수 있는 통로 폭 약 0.65 m**, 내접반경 0.215 를 빼면 실여유 양쪽 11 cm.
통과는 가능하지만 계획이 거의 중앙을 지나야 한다. NavFn 은 경로 길이를 아끼려 안쪽으로 붙는다.

→ 다음 후보: `cost_scaling_factor` 3.0 하향(비용이 더 완만하게 퍼져 중앙 선호가 강해진다),
  또는 `inflation_radius` 상향. **통로가 좁으므로 한 번에 하나씩 바꾸고 매번 계측한다.**

## 6. 부수적으로 배운 것

- **`job218_back.py`(직선 후진 복귀)는 설계가 틀렸다.** heading 이 틀어진 상태에서 후진하면
  대각선으로 밀린다. 실험을 반복하는 사이 로버가 출발점에서 **좌측 40 cm** 밀려나
  좌측 벽에 붙었고, 앞뒤가 모두 막혀 갇혔다. 복귀는 위치+자세를 함께 복원해야 한다
  (`job225_face.py` 로 heading 은 맞출 수 있으나 위치는 별도).
- 그때 "차체 좌측 뒤 유령" 이라고 판단했으나 **틀렸다** — 라이다가 차체 반경 0.6 m 안에
  103 점을 보고 있었다. 실물이었다. 코스트맵 격자를 찍어 보고서야 알았다.
- 로버가 **정지 중이면 slam 이 스캔을 처리하지 않아** `map->odom` 이 갱신되지 않는다.
  새로 붙은 TransformListener 는 그 TF 를 못 받아 "map does not exist" 가 난다.
  진단 스크립트는 map TF 대기 루프를 반드시 둔다.
- 재부팅 후에는 **base(micro-ROS 에이전트) → sensors → slam → nav2** 순서. base 를 빠뜨리면
  보드 토픽이 전멸해 "Nav2 활성화가 느리다" 처럼 보인다(09-10 과 같은 실수를 반복할 뻔했다).

## 2. SUMMARY.md

### 2.1 쓰는 시점 · 순서
- **작업하면서** 쓴다. 하루 끝에 몰아 쓰지 않는다(08-27 판의 '하루 마감 시 작성' 은 폐기).
- 절은 `§0, §1, …` **시간순**. 위에 그날 요약 몇 줄은 둘 수 있다.
- **정정은 지우지 않는다** — 새 § 에 쓰고, 틀린 § 에는 "→ §n 에서 정정" 만 덧붙인다.

### 2.2 주행 · 시험 절
- **판정 기준은 주행 전에** 선언한다(기준 · 예상값 · 합격선). 주행 뒤 기준을 바꾸면 그 사실을 적는다.
- **측정한 것과 추정을 구분**한다. 계산 · 추정 수치에는 '(계산)' · '(추정)', 확인 못 한 기전은 '미확인'.
- 기각한 가설도 근거와 함께 남긴다(재추진 방지).
- 부품 사양 수치는 출처(데이터시트 · 판매 페이지 · 실측 로그)를 함께 적을 때만 쓴다. 없으면 '미확인'(09-03 출처 불명 '3A' 사건).

### 2.3 추론 경로 · 데이터 칸
- 사용자가 같은 절차로 따라 추론할 수 있게 쓴다: **본 것 → 추론 → 결론**.
- **추론마다 데이터 위치**를 적는다 — 결과 원문(`outputs/`), 도구(`jobs/` · `Docs/tools/`), 입력 원천(bag 경로 · 토픽, Jetson 로그 경로), 그림.
- 휘발 위치(Jetson `/tmp` — prep · 재부팅이 지움, PC 스크래치패드 — 자동 삭제)에만 있는 것은 그날 `outputs/` · `bags/` 로 옮긴 뒤 그 경로를 쓴다. 못 옮겼으면 **'원천 소실'**.
- 읽기만 하는 확인 스크립트도 출력은 `| tee` 로 파일에 남긴다.
- **내 실수 · 정정**은 새 § 에 칸을 나눠 쓴다(한 줄 "정정" 금지). 본보기 `2026-10-20/SUMMARY.md §11`.

  | 칸 | 내용 |
  |---|---|
  | 하려 한 것 | 만든 스크립트 · 프로파일 이름 |
  | 본 것 | 출력 파일 · 수치 |
  | 처음 추론 | |
  | 의심한 이유 | 같은 창의 다른 지표와의 모순 등 |
  | 판별 시험 | |
  | 결론 | 기전을 모르면 '미확인' |
  | 다음에 알아보는 법 | 서명 · 규칙 |
  | 데이터 | 위 데이터 칸 |

## 3. 도구(스크립트)

### 3.1 이름 (10-12 결정 · 10-13 부터 적용)

## 4. Jetson 실행

- 실행은 **job 파일 + 러너 `run_jn.sh`**(목적 `JX_WHY` 필수)로만 한다. 인라인 heredoc 을 ssh 로 넘기지 않는다.
  - 러너는 머리글(시각 · 목적 · 원문 경로)과 출력을 Jetson `/tmp/live/current.log` 에 남긴다. 사용자는 `tail -F /tmp/live/current.log` 로 실시간으로 본다.
  - 실행 전에 한 줄로 알린다: 무엇을 · 왜 · 예상 시간 · 볼 곳.
- 러너(`run_jn.sh` · `run_f0.sh`)는 PC 스크래치패드에 있고, 7 일 넘은 파일은 자동 삭제된다 → **하루 시작 때 존재 확인 + `touch`**. 사라지면 저장소 사본(`<PW>` 가림)에서 복구, 비밀번호 값은 출력하지 않는다.
- Jetson 재부팅 뒤 `/tmp` 의 prep 스크립트가 지워진다 → 저장소 판을 다시 올린다(`Docs/tools/up_tools.sh`).
- `pkill -f` 는 Jetson 쪽 파일 안에서만(ssh 인라인 문자열에 프로세스 이름이 있으면 자기 셸을 죽임).
- **sudo · 호스트 설정 변경은 하지 않는다**(필요하면 사용자 결정).
- 출력에 MAC 주소가 나오면 가린다.
- 펌웨어 플래시는 반드시 `-rst`(없으면 MCU 정지 중 모터가 스스로 돎, 09-17), 플래시 뒤 한 번 더 `-rst`.

## 5. 주행

- **로버는 사용자가 "시작" 이라고 한 뒤에만 움직인다.** 배치 · 확인은 그 전에.
- 코스 배치 · 게이트 · 절차의 단일 출처 = `Docs/04_navigation/TEST_COURSE_AND_GATES.md`. Phase 가 바뀌면 절 단위로 검토해 새 판.
- 러너를 부를 때 `STAGE`(구성 단계) · `NOTE`(무엇을 바꿨나) · `GIT_HEAD` 를 **반드시** 채운다 → bag 폴더에 `run_meta.txt`(인자 · 기록 토픽 · 배포 파일 sha256) · `params.txt`(실행 중 파라미터) 가 남는다. 목적 = 개선 전후를 같은 코스 · 같은 토픽으로 나란히 비교. 기본 기록 토픽은 줄이지 않고 필요한 것은 `BAG_EXTRA` 로 더한다.
- 주행 전 검사는 중복 없이(10-27):
  - 러너 게이트 = `Docs/tools/chk_drive_gate.py` 한 노드.
  - 파라미터 확인 = `Docs/tools/chk_prep.py` 에 넣는다(`ros2 param get` 따로 부르지 않음).
  - 대화 쪽에서 따로 30 s 대기 · top 을 켜지 않는다 — 러너가 한다. "시작" 뒤 바로 러너, 실제 출발은 약 40~50 s 뒤라고 알린다.
  - 주행 30 s 전부터 DDS 참여자를 새로 만들지 않는다. Wi-Fi 재연결 뒤엔 스택 재기동.
- prep 출력은 필터 파이프로 거르지 말고 원문을 파일로 남긴 뒤 요약한다.
- 주행 직후 bag 을 PC `bags/` 로 회수한다(재부팅 · prep 이 Jetson `/tmp` 를 지움).

## 8. 비밀 · 공개 · 커밋 · push

- **Jetson SSH 비밀번호**: 커밋 파일 · 출력 · 대화에 쓰지 않는다. 사본에는 `<PW>`.
  - 보관 = **저장소 밖 `~/.config/rover_jetson/pw`**(PC, 11-02 사용자 결정). **한 줄에 하나 — 첫 줄 = 지금 값**(러너 복구 원천), 다음 줄부터 = 감시할 옛 값(게이트가 전부 검사). 비밀번호를 바꾸면 새 값을 첫 줄에 넣고 옛 값은 아래로 내린다.
  - 커밋 전 게이트 `git grep --cached -l "<비밀번호>" | wc -l` = **0 필수**(`git diff | grep` 은 삭제 줄까지 세므로 쓰지 않음).
  - 게이트 `Docs/tools/chk_commit_gate.py` 는 staged **와 추적 중인 작업 트리**를 본다(`git commit -a` · `git commit <파일>` 대비). 걸리거나 비밀번호 파일이 없으면 **막는다**.
    - Claude 커밋: `.claude/settings.json` PreToolUse 훅이 자동으로 부른다.
    - 터미널 커밋: git 자체 훅 `.git/hooks/pre-commit`(이 PC 만, 커밋 안 됨). 새로 clone 하거나 지워졌으면 다시 설치:
      `printf '#!/bin/sh
exec python "$(git rev-parse --show-toplevel)/Docs/tools/chk_commit_gate.py" --git-hook
' > .git/hooks/pre-commit && chmod +x .git/hooks/pre-commit`
- `.claude/settings.local.json`(앱이 승인한 명령이 쌓이는 개인 파일)은 **추적하지 않는다**(`.gitignore`). 05-21 ~ 11-02 추적되어 옛 비밀번호가 공개 이력에 남음 — 11-02 SUMMARY §6.
  - **명령 문자열에 비밀번호를 넣지 않는다** — 도구는 비밀번호를 파일(러너 · `~/.config/rover_jetson/pw`)에서 읽는다. 승인 창의 '다시 묻지 않음' 은 명령 문자열을 통째로 저장하기 때문.
  - 승인 창: 한 번 쓰는 명령은 **'이번만'**. 반복할 명령은 '다시 묻지 않음' 대신 와일드카드 규칙 한 줄을 `settings.local.json` 에 넣는다. 로버를 움직이거나 Jetson 에 쓰는 명령(러너 · 플래시)은 넣지 않는다(매번 확인).
- 웹 창구 키 `~/.config/rover_web/key`: 출력 · 커밋 금지.
- 공개 저장소에 나가면 안 되는 문구 목록은 비공개 쪽(`private/`)에 있다 — 공개되는 파일(이 파일 포함)에는 개인 계획 표현을 쓰지 않는다. 공개 스크립트가 점검하고 걸리면 멈춘다.
- **push 는 사용자 지시가 있을 때만**:
  1. `git fetch . feature/smac-hybrid:feature/nvblox-migration`
  2. `git push personal feature/nvblox-migration feature/smac-hybrid` (비공개 원본)
  3. `bash private/publish_public.sh` (공개 `dev`; `--push-main` 은 사용자 결정 때만)
  - `origin` 에는 올리지 않는다.
- 커밋 메시지 끝에 세션 지침이 주는 공동 작성자 줄을 붙인다.
- **커밋 전 점검** `python Docs/tools/chk_record_rules.py` (경고만 — 훅이 커밋 때 개수를 알림; `--all` = 10-13 이후 전부, `--strict` = 경고 시 종료 코드 1).
  보는 것: TOOLS.md 누락 · 도구 앞머리 · 스크립트 설명 주석 · 깨진 링크 · SUMMARY/TOOLS 에 적힌 `jobs/` `outputs/` 경로 존재 · 비밀번호 게이트. 경고는 고치거나, 고치지 않을 이유를 그날 SUMMARY 에 적는다.
- **기계적 차단**(`.claude/settings.json` deny): `git push origin …` · `git push public …`(공개는 점검이 있는 `publish_public.sh` 로만) · `sudo …`. 막히면 우회하지 말고 사용자에게 묻는다. 한계: ssh 문자열 안의 `sudo` 같은 간접 실행은 못 잡는다.
